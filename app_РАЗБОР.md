# Разбор файла app.py

## Что делает этот файл

Главный файл приложения. Содержит **только логику RAG-системы** и управление UI-взаимодействием: поиск по Qdrant, вызовы Groq API, обработчики кнопок. Весь визуал (CSS, HTML) вынесен в `дизайн.py`.

**Размер:** 393 строки. Все тяжёлые HTML-блоки заменены на вызовы `дизайн.показать_X()`.

## Системный промпт для LLM

```python
системный_промпт = """Ты — ассистент базы знаний...
1. Отвечай ТОЛЬКО на русском языке, даже если CONTEXT на английском.
2. Используй только факты из CONTEXT ниже. Не придумывай.
3. Если в CONTEXT есть хотя бы частичная информация — дай развёрнутый ответ.
4. Если CONTEXT состоит только из библиографии — скажи, что нужно переформулировать.
5. Если CONTEXT не относится к вопросу — скажи «В базе нет данных».
6. Термины оставляй в оригинале, давай перевод в скобках при первом упоминании.
7. В конце добавь раздел «Источники:» с новой строки.
8. Если найдена формула — выведи отдельным блоком с расшифровкой."""
```

**Зачем так строго:** RAG-модель по умолчанию склонна галлюцинировать. Эти 8 правил гарантируют:

- **Русский язык на выходе** (п.1) — даже если статья английская.
- **Нет галлюцинаций** (п.2) — только то, что есть в контексте.
- **Graceful degradation** (п.4–5) — при плохом контексте честно говорит «не знаю» вместо фантазии.
- **Читаемый формат** (п.7–8) — структурированный ответ, а не поток слов.

## Загрузка ресурсов (кэш)

```python
@st.cache_resource
def загрузить_модель():
    return SentenceTransformer("intfloat/multilingual-e5-base")

@st.cache_resource
def загрузить_qdrant():
    папка = os.path.join(os.path.dirname(os.path.abspath(__file__)), "qdrant_db")
    return QdrantClient(path=папка)
```

**`@st.cache_resource`** — декоратор Streamlit: результат вычисляется **один раз** за всё время жизни процесса. Модель (~400 МБ) и Qdrant-клиент грузятся только при первом запросе.

**Почему `cache_resource`, а не `cache_data`:** `cache_data` копирует значение каждый раз, `cache_resource` отдаёт один и тот же объект (подходит для клиентов БД, моделей).

## Фильтр библиографии

```python
def похоже_на_библиографию(текст):
    скобки = len(re.findall(r"\[\d{1,3}\]", текст))          # [1], [42]
    нум    = len(re.findall(r"(?:^|\n)\s*\d{1,4}\.\s+[A-ZА-ЯЁ]", текст, re.MULTILINE))
    et_al  = len(re.findall(r"\bet\s+al\.?", текст, re.IGNORECASE))
    doi    = len(re.findall(r"(?:doi[:\s\.]|10\.\d{4,}\s*/)", текст, re.IGNORECASE))
    http   = len(re.findall(r"https?://\S+", текст))
    годы   = len(re.findall(r"\((?:19|20)\d{2}\)", текст))
    авторы = len(re.findall(r"[A-ZА-ЯЁ][a-zа-яё\-]{2,}(?:\s+[A-Z]{1,3}[,\s]|,\s+[A-ZА-ЯЁ]\.)", текст))
    маркеры_бд = len(re.findall(r"\[(?:CrossRef|PubMed|Google\s+Scholar|DOI)\]", текст, re.IGNORECASE))
    return (скобки + нум + et_al + doi + http + годы + авторы + маркеры_бд) >= 6
```

**Проблема:** в PDF научных статей **список литературы** часто занимает 1–2 страницы. Qdrant их индексирует как обычные чанки. Когда LLM получает такой чанк — он видит только ссылки и не может ничего сказать.

**Решение:** считаем 8 разных ссылочных маркеров. Если суммарно ≥ 6 → чанк почти наверняка библиография → отбрасываем.

Примеры маркеров в библиографии:

- `[1]`, `[42]` — номера в квадратных скобках
- `1. Smith J.` — нумерованные пункты с заглавной буквы
- `et al.` — «и др.» по-английски
- `doi:10.1021/...` или `10.1021/...`
- `https://...`
- `(2019)` — год в скобках
- `Smith J.,` или `Smith, J.` — шаблон автора
- `[CrossRef]`, `[PubMed]` — маркеры научных баз

## Фильтр колонтитулов и таблиц-мусора

```python
_МУСОРНЫЕ_МАРКЕРЫ = (
    "licensed under a creative commons",
    "creativecommons.org/licenses",
    "view article online",
    "cc by license",
    "cc by-nc",
    "all rights reserved",
    "rights reserved",
    "published by elsevier",
    "open access article",
    "this journal is ©",
    "this is an open access",
)


def похоже_на_мусор(текст):
    """Колонтитулы журналов и развалившиеся таблицы из PDF — бесполезны для LLM."""
    т = текст.lower().strip()
    if len(т) < 60:
        return True
    if any(маркер in т for маркер in _МУСОРНЫЕ_МАРКЕРЫ):
        return True
    числовых = sum(1 for с in т if с.isdigit() or с in " .,()/-+")
    if числовых / len(т) > 0.6:
        return True
    return False
```

**Две проблемы, которые решает этот фильтр:**

### Проблема 1: Колонтитулы

Научные журналы (RSC, Elsevier, MDPI) печатают на каждой странице шаблонный футер вида:

```
This article is licensed under a Creative Commons Attribution 3.0 Unported Licence. View Article Online
CC BY license (http://creativecommons.org/licenses/by/4.0/). Data in brief 29 (2020) 105154
```

`pypdf` извлекает его вместе с основным текстом, `ingest.py` режет на чанки, и в Qdrant попадают **тысячи почти одинаковых векторов-колонтитулов**. Вектор у них близок к «центру» семантического пространства → косинусно похож почти на любой запрос → часто всплывает в топе.

### Проблема 2: Развалившиеся таблицы

`pypdf` не понимает структуру таблиц — читает их построчно, и ячейки сливаются в непрерывный поток чисел:

```
40 mm/sec) 58 58.42 10 60 70 190 125 27.6(630 mm/sec) 61.2 62.738 11 50 70 200 200...
18 000 40 14 000 30 10 000 20 6000 10 2000 4000 8000 12 000 16 000 00 2015 2016 2017...
```

Смысла для LLM — ноль, но опять же встречаются в выдаче.

### Как фильтр работает

Три проверки подряд, **любая** срабатывает → чанк отбрасывается:

1. **`len(т) < 60`** — слишком короткий, нет контекста.
2. **Подстроковая проверка маркеров** — если встречается любая из 11 фраз-колонтитулов → выкинуть. Выбраны именно такие, которые в обычном тексте *не встречаются* (никто не пишет «Creative Commons Attribution» в середине рассуждения про химию).
3. **Доля цифр и разделителей > 60%** — если текст почти целиком из чисел `0-9`, пробелов, `.,()/-+` → это сырые табличные данные.

### Почему два отдельных фильтра, а не один

`похоже_на_библиографию` и `похоже_на_мусор` ловят **разные** виды некачественных чанков. Библиография содержит авторов и DOI, мусор — колонтитулы и числа. Комбинировать в одну функцию — логически неверно и снижает гибкость. В `найти_похожие` они применяются через `and`:

```python
содержательные = [
    точка for точка in ответ.points
    if not похоже_на_библиографию(точка.payload.get("text", ""))
    and not похоже_на_мусор(точка.payload.get("text", ""))
]
```

**Эффект без переиндексации:** фильтры рантайм — применяются после того как Qdrant вернул топ-N. База остаётся как есть (46 026 векторов), но до пользователя доходит только чистое.

## Поиск похожих фрагментов

```python
def найти_похожие(вопрос, выбранный_кейс, количество):
    модель = загрузить_модель()
    клиент = загрузить_qdrant()
    вектор = модель.encode("query: " + вопрос, normalize_embeddings=True).tolist()

    если_фильтр = None
    if выбранный_кейс != "все":
        если_фильтр = Filter(must=[FieldCondition(key="case", match=MatchValue(value=выбранный_кейс))])

    ответ = клиент.query_points(
        collection_name="химия",
        query=вектор,
        limit=количество * 3,    # берём с запасом — 3× от нужного
        query_filter=если_фильтр,
        with_payload=True
    )

    содержательные = [
        точка for точка in ответ.points
        if not похоже_на_библиографию(точка.payload.get("text", ""))
        and not похоже_на_мусор(точка.payload.get("text", ""))
    ]
    if not содержательные:
        return ответ.points[:количество]
    return содержательные[:количество]
```

**Ключевой момент — префикс `"query: "`:** модель `multilingual-e5-base` обучена с двумя префиксами:

- `passage: ...` — для индексируемых документов (используется в `embed_resume.py`)
- `query: ...` — для поисковых запросов

**Если перепутать** — качество поиска упадёт на 20–30%.

**Почему `limit=количество * 3`:** фильтр библиографии может отсеять половину результатов. Берём с запасом, потом обрезаем.

**Fallback:** если все найденные точки оказались библиографией — возвращаем исходные (хотя бы что-то).

## Фолбэк Groq: ключи и модели

```python
def _ключи_groq():
    ключи = []
    for имя_переменной in ("GROQ_API_KEY", "GROQ_API_KEY_2", "GROQ_API_KEY_3"):
        к = os.getenv(имя_переменной)
        if к and к.strip():
            ключи.append(к.strip())
    return ключи
```

Собирает список ключей из `.env`. Поддерживает до трёх ключей (от разных аккаунтов). Пустые игнорирует.

```python
def _это_rate_limit(ошибка):
    текст = str(ошибка).lower()
    return "429" in текст or "rate_limit" in текст or "rate limit" in текст or "tokens per day" in текст
```

Распознаёт ошибку превышения суточного лимита Groq по характерным словам в исключении.

```python
def вызвать_groq(параметры_запроса, резервная_модель="llama-3.1-8b-instant"):
    ключи = _ключи_groq()
    if not ключи:
        raise RuntimeError("Не задан ни один GROQ_API_KEY в .env")

    основная_модель = параметры_запроса.get("model")
    модели_к_попытке = [основная_модель]
    if резервная_модель and резервная_модель != основная_модель:
        модели_к_попытке.append(резервная_модель)

    последняя_ошибка = None
    for модель in модели_к_попытке:
        параметры = dict(параметры_запроса, model=модель)
        for ключ in ключи:
            try:
                клиент = Groq(api_key=ключ)
                return клиент.chat.completions.create(**параметры)
            except Exception as ошибка:
                последняя_ошибка = ошибка
                if _это_rate_limit(ошибка):
                    continue
                raise
    raise последняя_ошибка
```

**Двухуровневый фолбэк:**

1. Пробуем **основную модель на всех ключах** (70b через GROQ_API_KEY, потом через GROQ_API_KEY_2).
2. Если все ключи дали 429 — пробуем **резервную модель на всех ключах** (8b имеет отдельную квоту 500k TPD).
3. Любая не-429 ошибка прерывает цепочку сразу (auth, network и т.д.).

**Зачем так сложно:** на защите приложение должно отвечать ВСЕГДА. Даже если 70b заблокирована на сутки — 8b обычно свободна.

## Основная функция: получение ответа

```python
def получить_ответ_от_groq(вопрос, фрагменты):
    if not _ключи_groq():
        return "Ошибка: GROQ_API_KEY не задан в файле .env"

    контекст = ""
    for i, фр in enumerate(фрагменты, 1):
        контекст += f"[{i}] Документ: {фр.payload['document']}, стр. {фр.payload['page']}\n"
        контекст += фр.payload["text"] + "\n\n"

    ответ = вызвать_groq({
        "model": "llama-3.3-70b-versatile",
        "messages": [
            {"role": "system", "content": системный_промпт},
            {"role": "user", "content": f"CONTEXT:\n{контекст}\n\nQUESTION:\n{вопрос}"}
        ],
        "temperature": 0.1,
        "max_tokens": 1500,
    })
    текст = ответ.choices[0].message.content
    return отрезать_источники(текст)
```

**Формирование контекста:** каждый найденный фрагмент нумеруется, указывается документ и страница. LLM видит 5–10 таких блоков и опирается только на них.

**`temperature=0.1`** — почти детерминированные ответы, меньше галлюцинаций. Чем выше температура, тем «творчнее» LLM.

**`max_tokens=1500`** — ограничение длины ответа. Примерно 1000–1200 слов русского текста.

## Вспомогательные функции

```python
def отрезать_источники(текст):
    совпадение = re.search(
        r"\n\s*(?:\*\*\s*|#+\s+)?(?:Источники|Sources|Ссылки)(?:\s*\*\*|\s*:|\s*\n)",
        текст, re.IGNORECASE,
    )
    if not совпадение:
        return текст.strip()
    return текст[:совпадение.start()].rstrip()
```

**Проблема:** LLM по инструкции пишет `**Источники:**\n[1] ...` в конце ответа, но мы форматируем источники **сами** в Python (красивее). Поэтому LLM-версию источников нужно отрезать.

**Регексп требует** чтобы слово «Источники» было **заголовком раздела** (с новой строки, заканчивается `**`, `:` или переносом). Фразы типа «эти источники показывают» НЕ матчатся — иначе ответ бы обрезался посреди предложения.

```python
def почистить_pdf_текст(текст):
    результат = re.sub(r"(\w)-\s*\n\s*(\w)", r"\1\2", текст)     # word-\nbreak → wordbreak
    результат = re.sub(r"\n(?!\s*\n)", " ", результат)           # одиночные \n → пробел
    результат = re.sub(r"\s*\b\d+\s+of\s+\d+\b\s*", " ", результат)  # "3 of 10"
    результат = re.sub(r" {2,}", " ", результат)                 # сжать пробелы
    return результат.strip()
```

PDF-экстракция через `pypdf` часто ломает слова переносами и раскидывает лишние переносы строк. Эта функция чистит мусор перед показом фрагмента пользователю.

## Предфильтр математики

```python
_МАТЕМАТИЧЕСКИЕ_СИМВОЛЫ = set("Σ∑∏∫∈∉≤≥≠≈∞αβγθσμπλ∗·×→∂∇√∝⊂⊃⊆⊇∪∩⟨⟩⇒⇔")

def содержит_математику(текст):
    if any(с in _МАТЕМАТИЧЕСКИЕ_СИМВОЛЫ for с in текст):
        return True
    if re.search(r"\b[a-zA-Zα-ωΑ-Ω]\s*\([a-zA-Z0-9,\s]+\)\s*=", текст):  # f(x) =
        return True
    if re.search(r"\b\w+\s*=\s*[\w\-+\d/·*().\[\]]{5,}", текст) and re.search(r"[_^]|\b\d+\b", текст):
        return True
    return False
```

**Зачем:** извлечение формул через LLM стоит ~900 токенов. Если делать для всех 10 фрагментов — это 9000 токенов в лимит на каждый вопрос.

Функция **быстро** (без API) проверяет: есть ли в тексте математические символы или шаблоны уравнений. Если нет — `извлечь_формулы()` вернёт пустой список без вызова LLM.

**Экономит ~60–70%** вызовов LLM для формул.

## Перевод фрагментов

```python
@st.cache_data(show_spinner=False)
def перевести_на_русский(текст):
    if not _ключи_groq():
        return текст
    try:
        ответ = вызвать_groq({
            "model": "llama-3.1-8b-instant",
            "messages": [
                {"role": "system", "content": "Ты переводчик научных текстов..."},
                {"role": "user", "content": текст}
            ],
            "temperature": 0.1,
            "max_tokens": 1000,
        })
        return ответ.choices[0].message.content
    except Exception:
        return текст
```

**`@st.cache_data`** — Streamlit кэширует перевод. Один и тот же английский фрагмент переводится только один раз за сессию. При повторном показе — мгновенно.

**Используем 8b модель** (не 70b) — перевод не требует глубокого понимания, важнее скорость и не тратить квоту 70b.

**`except Exception: return текст`** — если перевод упал, показываем оригинал. Приложение не ломается.

## Извлечение LaTeX формул

```python
@st.cache_data(show_spinner=False)
def извлечь_формулы(текст):
    if not содержит_математику(текст):
        return []                     # быстрый выход без LLM
    if not _ключи_groq():
        return []
    try:
        ответ = вызвать_groq({
            "model": "llama-3.1-8b-instant",
            "response_format": {"type": "json_object"},
            "messages": [
                {"role": "system", "content": "... конвертируй формулы в LaTeX, верни JSON ..."},
                {"role": "user", "content": текст}
            ],
            "temperature": 0.0,
            "max_tokens": 900,
        })
        сырой = ответ.choices[0].message.content
        данные = json.loads(сырой)
        if isinstance(данные, dict):
            for ключ in ("formulas", "формулы", "result", "items"):
                if ключ in данные and isinstance(данные[ключ], list):
                    return данные[ключ]
        return данные if isinstance(данные, list) else []
    except Exception:
        return []
```

**Входные данные:** грязный PDF-текст с символами типа `xopt ∈ argmin x∈X f(x)`.

**Выход:** список `[{"latex": "x_{opt} \\in \\arg\\min_{x \\in X} f(x)", "описание": "Оптимальное значение..."}]`.

**`response_format={"type": "json_object"}`** — режим принудительного JSON. Groq гарантирует валидный JSON на выходе, не надо парсить текст с regex.

**`temperature=0.0`** — максимальная детерминированность. Формула либо есть, либо нет — творчества не нужно.

## Демо-режим (offline fallback)

```python
def показать_демо_ответ(вопрос):
    вопрос_нижний = вопрос.lower()
    for запись in заготовленные_ответы:
        if any(слово in вопрос_нижний for слово in запись["вопрос"].lower().split()):
            return запись
    return заготовленные_ответы[0]
```

Грубый поиск по ключевым словам. Если хоть одно слово из эталонного вопроса есть в пользовательском — возвращаем соответствующий заготовленный ответ. Если ничего не подошло — возвращаем первый (безопасный fallback).

**Зачем:** если на защите упал интернет или Groq лёг — тумблер «Демо-режим» покажет 5 отрепетированных ответов.

## Обработчик кнопки «Найти ответ»

```python
if "результаты_поиска" not in st.session_state:
    st.session_state.результаты_поиска = None

if кнопка and вопрос_пользователя.strip():
    if демо_режим:
        with st.spinner("Поиск в демо-базе..."):
            демо = показать_демо_ответ(вопрос_пользователя)
        st.session_state.результаты_поиска = {"тип": "демо", "данные": демо}
    else:
        try:
            with st.spinner("Векторный поиск в Qdrant..."):
                точки = найти_похожие(вопрос_пользователя, выбор_кейса, количество_фрагментов)
            if not точки:
                st.session_state.результаты_поиска = None
                st.warning("Ничего не найдено...")
            else:
                with st.spinner("Генерация ответа · llama-3.3-70b..."):
                    ответ = получить_ответ_от_groq(вопрос_пользователя, точки)
                st.session_state.результаты_поиска = {
                    "тип": "rag",
                    "ответ": ответ,
                    "фрагменты": [{"document": т.payload["document"], ...} for т in точки],
                }
        except Exception as ошибка:
            st.session_state.результаты_поиска = None
            st.error(f"Ошибка подключения: {ошибка}")
```

**Почему результат в session_state, а не просто в переменной:** Streamlit перерисовывает страницу при любом взаимодействии (например, переключении тумблера перевода). Обычная переменная сбросится → ответ пропадёт. `session_state` сохраняет данные между перерисовками.

**`st.spinner(...)`** — показывает вертушку с сообщением пока выполняется код внутри `with`.

**Сохраняем не объекты Qdrant, а словари** — объекты Qdrant нельзя сериализовать, а `session_state` должен быть сериализуемым.

## Фрагменты с переводом и формулами

```python
дизайн.показать_заголовок("Найденные фрагменты", отступ_сверху_rem=3)
переводить = st.toggle("Показать перевод на русский", value=False,
                       key="переводить_фрагменты")

for i, фр in enumerate(фрагменты, 1):
    заголовок = f"{i:02d}   {фр['document']}   ·   стр. {фр['page']}   ·   score {фр['score']:.3f}"
    with st.expander(заголовок):
        st.markdown(f"**Кейс:** {получить_название_кейса(фр['case'])}")
        чистый = почистить_pdf_текст(фр["text"])

        with st.spinner("Поиск формул..."):
            формулы = извлечь_формулы(чистый[:2000])
        if формулы:
            st.markdown("**Формулы:**")
            for ф in формулы:
                латех = ф.get("latex", "")
                описание = ф.get("описание") or ф.get("description", "")
                if латех:
                    try:
                        st.latex(латех)
                    except Exception:
                        st.code(латех, language="latex")
                if описание:
                    st.caption(описание)
            st.markdown("---")

        if переводить:
            with st.spinner("Перевод..."):
                перевод = перевести_на_русский(чистый[:1500])
            st.markdown(перевод)
            if len(чистый) > 1500:
                st.caption("Показан перевод первых 1500 символов.")
        else:
            усечённый = чистый[:900] + ("…" if len(чистый) > 900 else "")
            st.markdown(усечённый)
```

**`st.expander`** — сворачиваемый блок. Заголовок всегда виден, содержимое раскрывается кликом.

**`st.latex(латех)`** — рендерит LaTeX-формулу красиво (через MathJax в браузере). Если формула невалидна — `except` покажет её как код.

**Ограничения длины:**

- `[:2000]` для извлечения формул — чтобы не превысить токены 8b.
- `[:1500]` для перевода — аналогично.
- `[:900]` для просмотра — чтобы expander не растягивался на пол-экрана.

## Что запомнить на защиту

1. **RAG = Retrieval-Augmented Generation.** Сначала находим релевантные фрагменты в Qdrant, потом отдаём их LLM как контекст вместе с вопросом.
2. **Префикс `query:`** для вопроса и `passage:` для документа — требование модели `multilingual-e5-base`.
3. **`cache_resource` кэширует тяжёлые объекты** (модель 400 МБ, клиент БД) — иначе они загружались бы на каждый запрос.
4. **Два фильтра качества чанков:** `похоже_на_библиографию` отсеивает списки литературы, `похоже_на_мусор` — колонтитулы журналов и развалившиеся таблицы. Оба работают рантайм, без переиндексации базы.
5. **Два уровня фолбэка Groq:** два ключа + две модели. На защите приложение отвечает всегда.
6. **Весь дизайн в `дизайн.py`** — в `app.py` только логика.
