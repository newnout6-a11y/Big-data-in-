## Системный промпт LLM (10 правил)

`системный_промпт` — строка из ~10 пронумерованных инструкций. Каждое правило — реакция на конкретный баг, который мы видели в продакшене:

| № | Содержание | Какой баг исправляет |
|---|---|---|
| 1 | Только русский, даже если CONTEXT английский | модель отвечала на английском |
| 2 | Только факты из CONTEXT, не придумывать | галлюцинации |
| 3 | При частичной информации — развёрнутый ответ | отказывалась на пограничных случаях |
| 4 | `[N]` в CONTEXT — это **наши** маркеры, не библиография | путала с References |
| 5 | Если CONTEXT нерелевантен — короткое «В базе нет данных» | писала длинные оправдания |
| 6 | Термины — в оригинале + рус. перевод в скобках | переводила `SMILES` → `СИУЛЕС` |
| 7 | **ОБЯЗАТЕЛЬНО** маркеры `[N]` после каждого факта; не на связки | без маркеров не было тултипов |
| 8 | НЕ добавлять раздел «Источники:» — мы выводим сами | дублирование блока |
| 9 | Главные формулы в `$$...$$`, inline `$...$` только для одной переменной | формулы сливались в строку |
| 10 | Запрещено приводить формулы, которых нет в CONTEXT | модель подставляла «общеизвестные» |

`temperature=0.1` дополнительно снижает креатив — почти детерминированный вывод.

## Загрузка ресурсов (с кэшем Streamlit)

```python
@st.cache_resource
```

`@st.cache_resource` — Streamlit-механизм. Объект создаётся **один раз при старте процесса** и переиспользуется при каждом нажатии кнопки. Без кэша:

- модель загружалась бы 8 секунд на каждый запрос;
- Qdrant создавал бы новое подключение и плодил блокировки на файлах БД.

Путь к БД считается от файла, а не от рабочей директории — чтобы не зависеть от того, откуда запустили `streamlit run`.

## Фильтр библиографии

```python
def похоже_на_библиографию(текст):
    скобки = len(re.findall(r"\[\d{1,3}\]", текст))
    нум = len(re.findall(r"(?:^|\n)\s*\d{1,4}\.\s+[A-ZА-ЯЁ]", текст, re.MULTILINE))
    et_al = len(re.findall(r"\bet\s+al\.?", текст, re.IGNORECASE))
    doi = len(re.findall(r"(?:doi[:\s\.]|10\.\d{4,}\s*/)", текст, re.IGNORECASE))
    http = len(re.findall(r"https?://\S+", текст))
    годы = len(re.findall(r"\((?:19|20)\d{2}\)", текст))
    авторы = len(re.findall(
        r"[A-ZА-ЯЁ][a-zа-яё\-]{2,}(?:\s+[A-Z]{1,3}[,\s]|,\s+[A-ZА-ЯЁ]\.)",
        текст
    ))
    маркеры_бд = len(re.findall(
        r"\[(?:CrossRef|PubMed|Google\s+Scholar|DOI)\]",
        текст, re.IGNORECASE
    ))
    return (скобки + нум + et_al + doi + http + годы + авторы + маркеры_бд) >= 6
```

Считаем 8 типов «библиографических маркеров»:

- `[12]`, `[15]` — ссылки на литературу;
- нумерованные списки авторов в начале строки;
- `et al.`;
- DOI;
- URL;
- даты `(2019)`;
- инициалы авторов `Smith J.,`;
- маркеры баз `[CrossRef]`, `[PubMed]`.

Если суммарно ≥6 → почти наверняка страница References. Чанк выкидывается.

**Логика «суммарно»** — если в обычном научном тексте вдруг встретилось 2 ссылки `[12]` и 1 DOI, это всё ещё нормальный текст. А вот если 4 даты + 5 авторов + 6 DOI — точно библиография.

## Чистка PDF-артефактов

```python
_PDF_ЗАМЕНЫ = (
    ("¼", "="),     # cmap: знак = в формулах превращается в дробь 1/4
    ("þ", "+"),     # исландский thorn → плюс
    ("ð", "("), ("Þ", ")"),  # исландские буквы → скобки
    ("¦", "|"),
    ("\u00ad", ""), # мягкий перенос
    ("\ufb01", "fi"), ("\ufb02", "fl"),  # лигатуры
)

def почистить_pdf_артефакты(текст):
    для_замены = текст
    for плохой, хороший in _PDF_ЗАМЕНЫ:
        для_замены = для_замены.replace(плохой, хороший)
    return для_замены
```

**Почему это нужно.** PDF-экстракторы (`pypdf`, `pdfplumber`) при наличии CID-маппингов в шрифте часто заменяют символы на другие Unicode-точки. Самые частые:

- `Y = m_факт / m_теор × 100%` → `Y ¼ m_факт / m_теор × 100%` (`=` стал `¼`).
- `f(x) + g(x)` → `f(x) þ g(x)` (`+` стал thorn'ом).

Без чистки:

- LLM видит `Y ¼` и не понимает формулу — отказывается отвечать или галлюцинирует.
- Тултипы показывают «кашу» вместо читаемого текста.

Применяется в `найти_похожие` сразу после Qdrant к каждому фрагменту перед показом и перед отправкой в LLM.

## Фильтр мусора

```python
def похоже_на_мусор(текст):
    т = текст.lower().strip()
    if len(т) < 60:
        return True
    if any(маркер in т for маркер in _МУСОРНЫЕ_МАРКЕРЫ):
        return True
    числовых = sum(1 for с in т if с.isdigit() or с in " .,()/-+|")
    if числовых / len(т) > 0.45:
        return True
    слова_букв = re.findall(r"[а-яёa-z]{3,}", т)
    длина_букв = sum(len(с) for с in слова_букв)
    if длина_букв / len(т) < 0.40:
        return True
    return False
```

Четыре уровня отбраковки:

1. **Слишком короткий** (<60 симв.) — обрывок, не полезен.
2. **Содержит мусорный паттерн** из `_МУСОРНЫЕ_МАРКЕРЫ`.
3. **>45% цифр и разделителей** — таблица из PDF, поток индексов.
4. **<40% «связных слов»** (3+ строчных букв подряд) — коды генов (`MW535279`), формулы без описания, подписи к рисункам.

Эвристики 3-4 ловят случаи, которые невозможно описать списком паттернов: например, страница с таблицей из 50 чисел.

## Перенос маркеров из формул

```python
def _вынести_маркеры_из_формул(текст):
    def обработать_блок(m):
        блок = m.group(0)
        маркеры = re.findall(r"\[\d+\]", блок)
        if not маркеры:
            return блок
        чистый = re.sub(r"\[\d+\]", "", блок)
        return чистый + "".join(маркеры)

    текст = re.sub(r"\$\$.+?\$\$", обработать_блок, текст, flags=re.DOTALL)
    текст = re.sub(r"\$[^$\n]+?\$", обработать_блок, текст)
    return текст
```

**Зачем нужна.** LLM иногда ставит маркер прямо внутри LaTeX-формулы:

```
$$\frac{m_{практ}[2]}{m_{теор}}$$
```

Streamlit рендерит `$$...$$` через KaTeX, который **парсит содержимое как математику** и удаляет любую HTML-разметку внутри. Наш `<span class="cite">[2]<span class="cite-tip">...</span></span>` исчезает — маркер становится некликабельным сырым текстом.

**Решение.** До замены `[N]` на span регексом находим формульные блоки, извлекаем оттуда все маркеры и приклеиваем их сразу за блок:

```
$$\frac{m_{практ}[2]}{m_{теор}}$$  →  $$\frac{m_{практ}}{m_{теор}}$$[2]
```

Теперь `[2]` снаружи формулы, KaTeX его не трогает, замена на span работает.

`re.sub` сначала обрабатывает блочные `$$...$$` (с `re.DOTALL` чтобы захватывать переносы строк), потом inline `$...$`. Регекс `[^$\n]+?` для inline исключает доллар и перенос строки, чтобы не съесть две формулы как одну.

## Вставка интерактивных цитат

```python
def вставить_цитаты_в_ответ(текст, фрагменты):
    if not фрагменты:
        return текст
    очищенный = re.sub(
        r"\n+\s*(?:#+\s+)?\*?\*?(?:Источники|Sources|References)\s*:?\*?\*?\s*[:\n].*$",
        "", текст, flags=re.IGNORECASE | re.DOTALL,
    ).rstrip()
    очищенный = _вынести_маркеры_из_формул(очищенный)
    безопасный = (очищенный.replace("&", "&amp;")
                          .replace("<", "&lt;")
                          .replace(">", "&gt;"))

    def замена(совпадение):
        n = int(совпадение.group(1))
        if not (1 <= n <= len(фрагменты)):
            return совпадение.group(0)
        фр = фрагменты[n - 1]
        полный_текст = фр.get("text", "")
        документ = фр.get("document", "")
        страница = фр.get("page", "")
        цитата = полный_текст[:800]
        if len(полный_текст) > 800:
            цитата += "…"
        ...
        return (
            f'<span class="cite">'
            f'[{n}]'
            f'<span class="cite-tip">'
            f'<span class="cite-doc">{doc_attr}</span>'
            f'<span class="cite-text">{text_attr}</span>'
            f'</span></span>'
        )

    return re.sub(r"\[(\d+)\]", замена, безопасный)
```

Что делает по шагам:

1. **Срезает раздел «Источники:»** из конца ответа (если LLM не послушалась правила 8).
2. **Выносит маркеры из формул** (предыдущая функция).
3. **Экранирует HTML** — `<` → `&lt;` и т. д. Это защита от случайных HTML-символов в тексте LLM. Markdown-конструкции (`**`, `_`, `$`) после экранирования остаются нетронутыми.
4. **Регексом `\[(\d+)\]`** находит все маркеры и подставляет HTML-структуру с тултипом:

```html
<span class="cite">
    [2]
    <span class="cite-tip">
        <span class="cite-doc">paper.pdf, стр. 3</span>
        <span class="cite-text">Реальный текст фрагмента до 800 символов...</span>
    </span>
</span>
```

CSS из `дизайн.py` делает `.cite-tip` видимым только при hover на `.cite`. На десктопе тултип фиксирован в правом нижнем углу viewport, на мобильном — по центру экрана.

**Защита `1 ≤ n ≤ len(фрагменты)`** — если LLM написала `[10]`, а у нас 5 фрагментов, маркер остаётся как сырой текст (не разбираем).

## Поиск похожих фрагментов в Qdrant

```python
def найти_похожие(вопрос, выбранный_кейс, количество):
    модель = загрузить_модель()
    клиент = загрузить_qdrant()
    вектор = модель.encode("query: " + вопрос, normalize_embeddings=True).tolist()

    если_фильтр = None
    if выбранный_кейс != "все":
        если_фильтр = Filter(
            must=[FieldCondition(key="case", match=MatchValue(value=выбранный_кейс))]
        )

    ответ = клиент.query_points(
        collection_name="химия",
        query=вектор,
        limit=количество * 3,
        query_filter=если_фильтр,
        with_payload=True
    )

    for точка in ответ.points:
        точка.payload["text"] = почистить_pdf_артефакты(точка.payload.get("text", ""))

    МИН_СХОДСТВО = 0.72
    релевантные = [т for т in ответ.points if т.score >= МИН_СХОДСТВО]

    содержательные = [
        точка for точка in релевантные
        if not похоже_на_библиографию(точка.payload["text"])
        and not похоже_на_мусор(точка.payload["text"])
    ]

    return содержательные[:количество]
```

Семь шагов:

1. **Кодируем вопрос** в 768-мерный вектор. Префикс `query:` обязателен для e5 — иначе качество поиска падает.
2. **Опционально применяем фильтр по кейсу** — Qdrant ищет только в подмножестве чанков с нужным `case`.
3. **Запрашиваем 3× от нужного количества** — фильтры выкинут часть, нам нужен запас.
4. **Чистим PDF-артефакты** в payload — потом эти данные пойдут и в тултипы, и в LLM.
5. **Порог релевантности 0.72**: для совсем нерелевантных вопросов e5 даёт скоры <0.72, для пограничных 0.72-0.80, для релевантных ≥0.80. 0.72 отсекает явный шум.
6. **Двойной фильтр мусора**: библиография + общий мусор.
7. **Срезаем до запрошенного количества**.

## Groq: ключи, обработка 429, автофолбэк

```python
def _ключи_groq():
    ключи = []
    for имя in ("GROQ_API_KEY", "GROQ_API_KEY_2", "GROQ_API_KEY_3"):
        к = os.getenv(имя)
        if к and к.strip():
            ключи.append(к.strip())
    return ключи

def _это_rate_limit(ошибка):
    текст = str(ошибка).lower()
    return "429" in текст or "rate_limit" in текст or "rate limit" in текст or "tokens per day" in текст

def вызвать_groq(параметры_запроса, резервная_модель="llama-3.1-8b-instant"):
    ключи = _ключи_groq()
    if not ключи:
        raise RuntimeError("Не задан ни один GROQ_API_KEY в .env")

    основная_модель = параметры_запроса.get("model")
    модели_к_попытке = [основная_модель]
    if резервная_модель and резервная_модель != основная_модель:
        модели_к_попытке.append(резервная_модель)

    последняя_ошибка = None
    for модель in модели_к_попытке:
        параметры = dict(параметры_запроса, model=модель)
        for ключ in ключи:
            try:
                клиент = Groq(api_key=ключ)
                return клиент.chat.completions.create(**параметры)
            except Exception as ошибка:
                последняя_ошибка = ошибка
                if _это_rate_limit(ошибка):
                    continue
                raise
    raise последняя_ошибка
```

**Двухуровневый фолбэк:**

```
для каждой модели [70b, 8b]:
    для каждого ключа [k1, k2, k3]:
        попробовать вызвать
        если 429 → следующий ключ
        если другая ошибка → пробросить наверх
```

Логика: TPD (token-per-day) Groq считается отдельно по каждому ключу и каждой модели. Если у первого аккаунта закончилась квота на 70b → пробуем второй ключ → третий → откатываемся на 8b (своя квота).

Не-rate-limit ошибки (5xx, неверный формат) пробрасываются сразу — нет смысла повторять.

## Получение ответа от Groq

```python
def получить_ответ_от_groq(вопрос, фрагменты):
    if not _ключи_groq():
        return "Ошибка: GROQ_API_KEY не задан в файле .env"

    контекст = ""
    for i, фр in enumerate(фрагменты, 1):
        контекст += f"[{i}] Документ: {фр.payload['document']}, стр. {фр.payload['page']}\n"
        контекст += фр.payload["text"] + "\n\n"

    ответ = вызвать_groq({
        "model": "llama-3.3-70b-versatile",
        "messages": [
            {"role": "system", "content": системный_промпт},
            {"role": "user", "content": f"CONTEXT:\n{контекст}\n\nQUESTION:\n{вопрос}"}
        ],
        "temperature": 0.1,
        "max_tokens": 1500,
    })
    текст = ответ.choices[0].message.content
    текст = отрезать_источники(текст)
    текст = убрать_неверные_маркеры(текст, фрагменты)
    return текст
```

**Структура CONTEXT:**

```
[1] Документ: paper1.pdf, стр. 3
Текст первого фрагмента целиком...

[2] Документ: paper2.pdf, стр. 5
Текст второго фрагмента...

[3] ...
```

Метки `[1]`, `[2]` дальше используются LLM в ответе как ссылки на конкретные фрагменты. По правилу 4 системного промпта, модель **обязана** понимать, что это **наши** маркеры, а не библиография.

После Groq — две пост-обработки:

1. `отрезать_источники` — убирает раздел «Источники:» если LLM добавила его в конец вопреки правилу 8.
2. `убрать_неверные_маркеры` — embedding-пост-проверка цитат.

## Embedding-пост-проверка маркеров

Это **главная защита от ошибок нумерации**. Системный промпт не справляется на 100% — LLM иногда путает номера фрагментов.

```python
def убрать_неверные_маркеры(ответ, фрагменты, абс_порог=0.65, дельта=0.015, ratio=0.97):
    if not фрагменты or "[" not in ответ:
        return ответ

    маркеры = []
    for m in re.finditer(r"\[(\d+)\]", ответ):
        n = int(m.group(1))
        if not (1 <= n <= len(фрагменты)):
            continue
        start = m.start()
        границы = [
            ответ.rfind(sep, 0, start)
            for sep in (". ", "! ", "? ", "\n", ": ", "; ", ", ")
        ]
        начало = max(границы) + 2 if any(b >= 0 for b in границы) else 0
        утв_сырой = ответ[начало:start].strip()
        утв = re.sub(r"\[\d+\]", "", утв_сырой).strip()
        if len(утв) < 20:
            continue
        маркеры.append({"start": m.start(), "end": m.end(), "n": n, "утв": утв})

    if not маркеры:
        return ответ

    try:
        модель = загрузить_модель()
        уник_утв = list({м["утв"] for м in маркеры})
        тексты_ф = [
            (фр.get("text") if isinstance(фр, dict) else фр.payload.get("text", ""))
            for фр in фрагменты
        ]
        emb_утв = модель.encode(["query: " + t for t in уник_утв], normalize_embeddings=True)
        emb_ф = модель.encode(["passage: " + t for t in тексты_ф], normalize_embeddings=True)
        матрица = emb_утв @ emb_ф.T

        индекс = {t: i for i, t in enumerate(уник_утв)}
        для_удаления = []
        for м in маркеры:
            i = индекс[м["утв"]]
            sim = float(матрица[i, м["n"] - 1])
            max_sim = float(матрица[i].max())
            если_слабый = sim < абс_порог
            если_отстаёт_абсолютно = sim < max_sim - дельта
            если_отстаёт_относительно = sim < max_sim * ratio
            if если_слабый or если_отстаёт_абсолютно or если_отстаёт_относительно:
                для_удаления.append((м["start"], м["end"]))
    except Exception:
        return ответ

    if not для_удаления:
        return ответ

    для_удаления.sort(reverse=True)
    чистый = ответ
    for start, end in для_удаления:
        if start > 0 and чистый[start - 1] == " ":
            start -= 1
        чистый = чистый[:start] + чистый[end:]
    чистый = re.sub(r" {2,}", " ", чистый)
    return чистый
```

**Алгоритм:**

1. Найти все маркеры `[N]` в ответе.
2. Для каждого маркера выделить «утверждение» — текст до маркера от ближайшей границы (`. `, `! `, `\n`, `, `, `; `, `: `).
3. Слишком короткие утверждения (<20 символов) — связки типа «Поэтому [1]» — пропускаем.
4. Закодировать утверждения и фрагменты в embedding'и (с правильными префиксами `query:` / `passage:`).
5. Посчитать матрицу сходств `[len(утверждений) × len(фрагментов)]`.
6. Для каждого маркера проверить три критерия плохости:
   - **`sim < абс_порог`** (0.65) — фрагмент N вообще не про это утверждение.
   - **`sim < max_sim - дельта`** (0.015) — есть фрагмент с явно лучшим сходством.
   - **`sim < max_sim * ratio`** (0.97) — sim хуже max более чем на 3%.

Если хотя бы один критерий истинен → маркер удаляется.

7. Удаляем с конца строки (чтобы не сдвигались индексы), убираем лишние пробелы.

**Пример работы.** LLM написала «η — выход реакции, m_практическая — масса продукта [1]», но фрагмент 1 — это задача про фосфат натрия. Cos-sim получится ~0.79 vs 0.84 для фрагмента 2 (с реальной формулой). Разница 0.05 > δ=0.015 → `[1]` удаляется.

**Калибровка.** Параметры подбирались итеративно по реальным скриншотам ошибок. Тройной критерий компенсирует случаи, когда нужно поймать пограничный промах (sim ≈ max-0.02), но не удалять легитимную множественную поддержку (sim ≈ max-0.005).

**Время работы:** ~200 мс. Embedding-модель уже в кэше, второе кодирование быстрое.

**Откат на ошибку:** в `try-except` — если модель/numpy упали, возвращаем ответ как есть. Лучше показать ответ с возможной ошибкой, чем сломать всю страницу.

## Удаление раздела «Источники» из ответа LLM

```python
def отрезать_источники(текст):
    совпадение = re.search(
        r"\n\s*(?:\*\*\s*|#+\s+)?(?:Источники|Sources|Ссылки)(?:\s*\*\*|\s*:|\s*\n)",
        текст, re.IGNORECASE,
    )
    if not совпадение:
        return текст.strip()
    return текст[:совпадение.start()].rstrip()
```

Регекс матчит **только заголовок раздела**: слово «Источники/Sources/Ссылки» с начала строки, после которого идёт `:`, `**` (markdown bold) или перенос. Не срабатывает на упоминание слова в обычной фразе («Эти источники дают…»).

Если совпадение найдено — обрезаем всё начиная с этой позиции. Свой блок «Источники» мы потом отрисуем в `дизайн.py` сами, на основе фрагментов.

## Чистка PDF-текста для отображения

```python
def почистить_pdf_текст(текст):
    результат = re.sub(r"(\w)-\s*\n\s*(\w)", r"\1\2", текст)
    результат = re.sub(r"\n(?!\s*\n)", " ", результат)
    результат = re.sub(r"\s*\b\d+\s+of\s+\d+\b\s*", " ", результат)
    результат = re.sub(r" {2,}", " ", результат)
    return результат.strip()
```

Применяется при показе фрагмента в expander'е (раскрывающемся блоке). Делает текст более читаемым:

1. **Склеивает переносы слов**: `моле-\nкула` → `молекула`.
2. **Превращает одиночные `\n` в пробелы** — параграфы остаются (двойной `\n` сохраняется).
3. **Убирает «висящие» номера страниц**: `... текст 5 of 12 ещё текст` → `... текст ещё текст`.
4. **Схлопывает множественные пробелы**.

## Перевод и извлечение формул через 8B

```python
@st.cache_data(show_spinner=False)
def перевести_на_русский(текст):
    if not _ключи_groq():
        return текст
    ответ = вызвать_groq({
        "model": "llama-3.1-8b-instant",
        "messages": [...],
        "temperature": 0.1,
        "max_tokens": 1000,
    })
    return ответ.choices[0].message.content

@st.cache_data(show_spinner=False)
def извлечь_формулы(текст):
    if not содержит_математику(текст):
        return []
    ответ = вызвать_groq({
        "model": "llama-3.1-8b-instant",
        "response_format": {"type": "json_object"},
        ...
    })
    данные = json.loads(ответ.choices[0].message.content)
    return данные.get("formulas", [])
```

Обе функции:

- **Используют 8B модель** — это экономит TPD основной 70B на ответы пользователю.
- **Кэшируются через `@st.cache_data`** — повторные вызовы на тот же текст возвращают кэш.

`содержит_математику(текст)` — быстрый предфильтр. Если текст не содержит математических символов (`Σ`, `∑`, `=`, `e^x`, и т. п.), не тратим LLM-токены на поиск формул.

`извлечь_формулы` использует Groq в **JSON mode** (`response_format={"type": "json_object"}`) — модель обязана вернуть валидный JSON. Промпт содержит подробную таблицу конвертации Unicode → LaTeX.

`app.py` собирает в один процесс:

- **загрузку модели и Qdrant** (один раз, кэшируется);
