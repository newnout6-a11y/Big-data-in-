# Разбор файла embed_resume.py

## Что делает этот файл

Берёт чанки из `chunks.jsonl`, превращает каждый в 768-мерный вектор через модель `multilingual-e5-base` и складывает в Qdrant. **Главная особенность** — скрипт инкрементальный: если уже есть точки в базе, догружает только новые (не переделывает всё с нуля).

**Зачем инкрементальность:** векторизация 46 000 чанков на CPU занимает 10–30 минут. Если процесс прервался (закрыл терминал, отвалился интернет) — можно запустить заново и продолжить с того же места.

---

## Импорты и константы

```python
import os
import json
from sentence_transformers import SentenceTransformer
from qdrant_client import QdrantClient
from qdrant_client.models import PointStruct

файл_чанков = os.path.join(os.path.dirname(os.path.abspath(__file__)), "chunks.jsonl")
папка_базы = os.path.join(os.path.dirname(os.path.abspath(__file__)), "qdrant_db")
название_коллекции = "химия"
размер_батча = 64
```

**Пути через `os.path.dirname(__file__)`:** работает независимо от того, из какой папки запускаешь скрипт. `embed_resume.py` сам определяет где он лежит.

**`размер_батча = 64`:** за один вызов `модель.encode()` векторизуем 64 чанка. Чем больше — тем эффективнее, но больше памяти. 64 — хороший баланс на средней машине.

**`название_коллекции = "химия"`:** имя коллекции в Qdrant (аналог таблицы в SQL).

---

## Подключение к Qdrant и подсчёт загруженного

```python
клиент = QdrantClient(path=папка_базы)

уже_в_базе = клиент.count(название_коллекции).count
print(f"В базе уже: {уже_в_базе} точек")
```

**`QdrantClient(path=...)`** — embedded-режим: Qdrant запускается внутри процесса Python, БД хранится в файлах папки `qdrant_db/`. Не требует Docker или отдельного сервера.

**`клиент.count(название_коллекции).count`** — API возвращает объект со счётчиком, берём поле `.count`. Двойное `.count` выглядит странно, но так устроен qdrant-client.

**Если коллекция не существует** — скрипт упадёт с ошибкой. Значит первый раз нужно создать коллекцию вручную (это единственный недостаток инкрементальной версии). Либо убедиться, что коллекция уже есть после первого запуска.

## Чтение чанков из jsonl

```python
все_чанки = []
with open(файл_чанков, "r", encoding="utf-8") as файл:
    for строка in файл:
        строка = строка.strip()
        if строка:
            все_чанки.append(json.loads(строка))

print(f"Всего чанков в файле: {len(все_чанки)}")
```

**Формат `chunks.jsonl`:** одна строка — один JSON-объект (JSON Lines). Это стандарт для больших датасетов — можно читать построчно, не загружая всё в память.

Пример строки:

```json
{"text": "...", "document": "s13321.pdf", "page": 3, "case": "токсичность"}
```

**`if строка:`** пропускаем пустые строки (бывают в конце файла).

## Определение что осталось

```python
осталось = все_чанки[уже_в_базе:]
print(f"Осталось загрузить: {len(осталось)}")

if not осталось:
    print("Нечего загружать, база уже заполнена")
    import sys
    sys.exit(0)
```

**Ключевая логика:** срез `[уже_в_базе:]` берёт чанки начиная с индекса = число точек в базе. **Предположение** — порядок чанков в файле соответствует порядку точек в базе (их ID идут 0, 1, 2, ...).

**Это работает корректно если:**

- `ingest.py` выводит чанки в детерминированном порядке (`sorted(os.listdir)` — да, работает).
- Между запусками `embed_resume` файл `chunks.jsonl` не переупорядочивается.

**Если условия не соблюдены** — старые точки смешаются с новыми, но данные не потеряются (IDs уникальны).

**Если уже всё в базе — выход без ошибки** (`sys.exit(0)` = success).

## Загрузка модели

```python
модель = SentenceTransformer("intfloat/multilingual-e5-base")
print("Модель загружена")
```

**`intfloat/multilingual-e5-base`** — модель от Microsoft/Beijing Academy. Поддерживает 100+ языков, выдаёт 768-мерные векторы.

Размер модели ~400 МБ, качается с Hugging Face при первом запуске, кэшируется в `~/.cache/huggingface/`.

## Векторизация и загрузка батчами

```python
текущий_ид = уже_в_базе

for старт in range(0, len(осталось), размер_батча):
    батч = осталось[старт:старт + размер_батча]

    тексты = ["passage: " + ч["text"] for ч in батч]
    векторы = модель.encode(тексты, show_progress_bar=False, normalize_embeddings=True)

    точки = []
    for i, чанк in enumerate(батч):
        точки.append(PointStruct(
            id=текущий_ид,
            vector=векторы[i].tolist(),
            payload={
                "text": чанк["text"],
                "document": чанк["document"],
                "page": чанк["page"],
                "case": чанк["case"]
            }
        ))
        текущий_ид += 1

    клиент.upsert(collection_name=название_коллекции, points=точки)

    if (старт // размер_батча + 1) % 10 == 0 or старт + размер_батча >= len(осталось):
        всего_готово = уже_в_базе + min(старт + размер_батча, len(осталось))
        print(f"  Загружено в Qdrant: {всего_готово}/{len(все_чанки)}")
```

### Префикс `"passage: "`

**Критично!** Модель `multilingual-e5-base` обучена с двумя префиксами:

- `"passage: "` — для **индексируемых документов** (это здесь)
- `"query: "` — для **поисковых запросов** (в `app.py` → `найти_похожие`)

Если поменять местами — качество поиска падает на 20–30%.

### `normalize_embeddings=True`

Нормализует каждый вектор к длине 1. Почему важно:

- Косинусная метрика sim(A, B) = A · B / (|A| · |B|).
- Если векторы уже нормализованы — это просто A · B (скалярное произведение).
- Qdrant с `distance=Cosine` ожидает нормализованные векторы и так считает быстрее.

### `PointStruct`

Единица данных в Qdrant:

- `id` — целое число или UUID. Используем `текущий_ид`, который инкрементируется: 0, 1, 2, ...
- `vector` — список из 768 float. `.tolist()` превращает numpy-массив в обычный список Python (Qdrant требует JSON-совместимый тип).
- `payload` — словарь метаданных, индексируется для фильтрации (ищем по `case`, показываем `document` и `page`).

### `клиент.upsert`

**Upsert = update or insert.** Если ID уже есть — перезаписывается, если нет — создаётся. Это идемпотентно: можно запустить скрипт дважды, и он не создаст дубликатов, а просто перезапишет.

### Прогресс каждые 10 батчей

```python
if (старт // размер_батча + 1) % 10 == 0 or старт + размер_батча >= len(осталось):
```

Печатаем прогресс каждые 10 батчей (640 чанков) или на последнем батче. Иначе терминал забивается сотнями строк.

## Как это связано с другими файлами

```
ingest.py                 embed_resume.py              app.py
   │                           │                          │
   │ читает all_pdfs/          │                          │
   │ разбивает на чанки        │                          │
   │ определяет кейс           │                          │
   ▼                           ▼                          ▼
chunks.jsonl  ─────────►  векторизует  ────────►  qdrant_db/
                          кладёт в БД              ищет похожие
                                                   возвращает точки
```

- **Вход:** `chunks.jsonl` от `ingest.py`
- **Выход:** `qdrant_db/` — читается `app.py` при поиске
- **Модель:** та же что в `app.py` (`multilingual-e5-base`). Размерность векторов должна совпадать, иначе Qdrant откажется принимать.

## Первый запуск на чистой машине

`embed_resume.py` требует **существующую** коллекцию в Qdrant, иначе `клиент.count(...)` упадёт. Для первого создания коллекции можно сделать так:

```python
from qdrant_client import QdrantClient
from qdrant_client.models import Distance, VectorParams

клиент = QdrantClient(path="qdrant_db")
клиент.create_collection(
    collection_name="химия",
    vectors_config=VectorParams(size=768, distance=Distance.COSINE)
)
```

После этого `embed_resume.py` работает стандартно.

## Что будет если...

| Ситуация | Поведение |
|---|---|
| Прервал посреди работы | При повторном запуске продолжит с того же места |
| Добавил новых PDF и перезапустил `ingest.py` | Новые чанки будут в конце `chunks.jsonl`, `embed_resume.py` догрузит их |
| Коллекции ещё нет | Падает с ошибкой — нужно сначала её создать |
| Файл `chunks.jsonl` короче чем точек в БД | Выход без ошибки, считает что всё загружено |
| Два запуска одновременно | Qdrant в embedded-режиме блокирует папку — второй упадёт |

## Что запомнить на защиту

1. **Инкрементальная логика через срез `[уже_в_базе:]`** — простейший, но рабочий способ продолжить с места остановки.
2. **Префикс `"passage: "`** обязателен для модели E5 при индексации. Без него — потеря качества.
3. **`normalize_embeddings=True`** нужен для корректной работы косинусной метрики в Qdrant.
4. **Batch size 64** — баланс между скоростью и памятью на обычном ноутбуке.
5. **`upsert` идемпотентен** — можно запускать сколько угодно раз, данные не задублируются.
