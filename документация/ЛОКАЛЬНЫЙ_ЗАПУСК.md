# Локальный запуск harvester'а

Качаем и эмбеддим документы прямо на ПК. Никакого облака, никаких GH Actions. Всё пишется в `qdrant_db/` и `all_pdfs/` рядом с репо.

## Один раз: установка

```bash
git clone https://github.com/newnout6-a11y/Big-data-in-.git
cd Big-data-in-
pip install -r requirements.txt
```

Установится Python-зависимости (sentence-transformers, qdrant-client, fastembed, pymupdf, и т. д.). Модели e5 (~500 МБ) и BM25 (~25 КБ) докачаются при первом запуске; reranker (~600 МБ) — только когда включишь чекбокс в UI.

## Ручной запуск

**Windows** — двойной клик по `run_harvester.bat`. Или из cmd:

```cmd
run_harvester.bat
```

**Linux / macOS:**

```bash
./run_harvester.sh
```

По умолчанию: бюджет 200 документов, все 6 источников, год от 2020. Меняем через env:

```bash
HARVESTER_BUDGET=500 HARVESTER_SOURCES=arxiv,europepmc ./run_harvester.sh
```

После прогона:
- PDF/TXT — в `all_pdfs/`
- метадата — в `harvested_meta/`
- чанки — в `chunks_v2.jsonl`
- векторы — в `qdrant_db/` (Qdrant embedded), коллекция `knowledge_hybrid`

Запустить Streamlit и искать:

```bash
streamlit run app.py
```

## Бесконечный цикл (работа 100-140 мин → сон 20-40 мин → повтор)

Для непрерывного сбора на своём ПК. Главное отличие от Task Scheduler: тайминги рандомные, скрипт сам продолжает после ошибок, между источниками добавляется естественный jitter.

**Windows:**
```cmd
run_harvester_loop.bat
```

**Linux / macOS:**
```bash
./run_harvester_loop.sh
```

Остановить — `Ctrl+C` в том же окне (корректно дожмёт текущую итерацию).

### Авто-старт при входе / после перезагрузки

**Windows (Task Scheduler):**
1. Планировщик заданий → **Создать задачу…** (не простую)
2. Триггер → **При входе в систему**
3. Действие → Запуск программы → путь к `run_harvester_loop.bat`
4. Рабочая папка: папка проекта
5. Условия → снять «Запускать только при питании от сети»

Теперь каждый раз после перезагрузки цикл сам запускается.

**Linux (systemd --user):**

`~/.config/systemd/user/harvester.service`:

```ini
[Unit]
Description=Big-data harvester loop
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/home/you/Big-data-in-
ExecStart=/home/you/Big-data-in-/run_harvester_loop.sh
Restart=always
RestartSec=30

[Install]
WantedBy=default.target
```

```bash
systemctl --user daemon-reload
systemctl --user enable --now harvester
loginctl enable-linger $USER   # чтобы работало без сессии
```

### Тайминги

По умолчанию 100-140 минут работы, 20-40 минут сна. Поменять:

```cmd
set HARVEST_WORK_MIN_LOW=60
set HARVEST_WORK_MIN_HIGH=90
set HARVEST_SLEEP_MIN_LOW=10
set HARVEST_SLEEP_MIN_HIGH=20
run_harvester_loop.bat
```

## Автоматический запуск (по расписанию)

### Windows: Task Scheduler

1. Пуск → набираем «Планировщик заданий» → открываем
2. **Действие → Создать задачу...** (не «простую», нужна обычная)
3. Вкладка **Общие**:
   - Имя: `Big-data harvester`
   - «Выполнять только для вошедших пользователей» (если ПК всегда твой)
4. Вкладка **Триггеры → Создать**:
   - «Ежедневно» или «При входе в систему»
   - Если ежедневно — поставь «Повторять задачу каждые 6 часов в течение 1 дня»
5. Вкладка **Действия → Создать**:
   - Действие: «Запуск программы»
   - Программа: `C:\путь\к\проекту\Big-data-in-\run_harvester.bat`
   - **Рабочая папка:** `C:\путь\к\проекту\Big-data-in-` (важно!)
6. Вкладка **Условия:**
   - Снять «Запускать только при питании от сети» если на ноутбуке
7. **OK**, спросит пароль — введи пароль учётки Windows

Проверить — правый клик на задаче → «Выполнить». В папке проекта появятся свежие файлы.

### Linux / macOS: cron

Открыть crontab:

```bash
crontab -e
```

Добавить строку (раз в 6 часов):

```
0 */6 * * * cd /home/you/Big-data-in- && ./run_harvester.sh >> /home/you/harvester.log 2>&1
```

Проверить:

```bash
crontab -l
tail -f ~/harvester.log
```

### macOS launchd (альтернатива cron)

Файл `~/Library/LaunchAgents/com.user.harvester.plist`:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Label</key><string>com.user.harvester</string>
    <key>ProgramArguments</key>
    <array>
      <string>/Users/you/Big-data-in-/run_harvester.sh</string>
    </array>
    <key>WorkingDirectory</key><string>/Users/you/Big-data-in-</string>
    <key>StartInterval</key><integer>21600</integer>
    <key>StandardOutPath</key><string>/Users/you/harvester.log</string>
    <key>StandardErrorPath</key><string>/Users/you/harvester.log</string>
</dict>
</plist>
```

Загрузить:

```bash
launchctl load ~/Library/LaunchAgents/com.user.harvester.plist
```

## Полезные параметры

```bash
# Только один источник:
HARVESTER_SOURCES=arxiv ./run_harvester.sh

# Только свежак (с 2024):
HARVESTER_YEAR_MIN=2024 ./run_harvester.sh

# Большой бюджет (предупреждение: будет качать долго):
HARVESTER_BUDGET=2000 ./run_harvester.sh

# Сменить email для OpenAlex/Europe PMC (важно: эти API хотят настоящий email):
HARVESTER_EMAIL=your.real@email.com ./run_harvester.sh
```

## Когда что-то идёт не так

- **«python не является внутренней или внешней командой»** (Windows) — Python не в PATH. Скрипт сам ищет: `py -3` → `python` → стандартные папки `Programs\Python\Python31x\python.exe`. Если не нашёл — задай явно перед запуском:

  ```cmd
  set "PYTHON_EXE=C:\Users\Redmi\AppData\Local\Programs\Python\Python312\python.exe"
  run_harvester.bat
  ```

  Постоянно: System Properties → Environment Variables → New User Variable → Name `PYTHON_EXE`, Value путь к python.exe.

- **Кракозябры в выводе .bat** — терминал в cp866. Скрипт ставит `chcp 65001` (UTF-8) автоматически. Если всё равно мусор — открой cmd, выполни `chcp 65001`, потом `run_harvester.bat`.

- **Долго качается e5-base или reranker** — это один раз при первом запуске. Кешируется в `~/.cache/huggingface/`.

- **Disk full** — `all_pdfs/` может расти быстро. Если место кончается, удали старые: `find all_pdfs -mtime +30 -delete` (Linux) / в проводнике (Windows).

- **HTTP 429 / rate limits** — снизь `HARVESTER_BUDGET` или запускай реже.

## Бэкап в S3 (Sber Cloud / Cloudflare R2 / Backblaze B2)

Опционально: после каждой итерации цикла новые PDF + metadata можно синхронизировать в S3-совместимое облако. Движок один и тот же (boto3), меняется только endpoint.

### Sber Cloud OBS

1. В личном кабинете Сбера создай бакет (например `harvester-raw`) и IAM-ключи с правом `PutObject` в этот бакет.
2. Задай 4 env-переменные перед запуском:

   **Windows:**
   ```cmd
   set S3_ENDPOINT_URL=https://obs.ru-moscow-1.hc.sbercloud.ru
   set S3_BUCKET=harvester-raw
   set S3_ACCESS_KEY=AK...
   set S3_SECRET_KEY=SK...
   run_harvester_loop.bat
   ```

   **Linux/macOS:**
   ```bash
   export S3_ENDPOINT_URL=https://obs.ru-moscow-1.hc.sbercloud.ru
   export S3_BUCKET=harvester-raw
   export S3_ACCESS_KEY=AK...
   export S3_SECRET_KEY=SK...
   ./run_harvester_loop.sh
   ```

3. Постоянно: Windows → Environment Variables → New User Variable (те же 4 ключа).

После каждой итерации harvester сольёт новые файлы (пропуская уже загруженные через `HeadObject`). Логи:
```
[s3 12/45] PUT all_pdfs/recursive-multi-agent__arxiv-2604.25917v1.pdf (13063 КБ)
[s3 13/45] PUT harvested_meta/recursive-multi-agent__arxiv-2604.25917v1.json (2 КБ)
[s3] итого: залито 24, пропущено (уже было) 21, ошибок 0
```

Выключить S3 upload — просто не задавать `S3_BUCKET`.

### Cloudflare R2 (альтернатива)

```cmd
set S3_ENDPOINT_URL=https://<account_id>.r2.cloudflarestorage.com
set S3_REGION=auto
set S3_BUCKET=harvester-raw
set S3_ACCESS_KEY=...
set S3_SECRET_KEY=...
```

### Проверка вручную

```bash
python -m harvester.s3_upload --dry-run   # покажет что бы залилось
python -m harvester.s3_upload             # реально зальёт
```
