# Гибридный поиск + Reranker

## Что и зачем

Раньше поиск был только по dense-эмбеддингам (e5-base, 768d):
```
вопрос → e5 → вектор → cosine с БД → top-K → Groq → ответ
```

Это хорошо ловит семантику, но плохо — редкие термины: конкретные молекулы,
аббревиатуры (DFT, GNN), номера патентов, формулы. Для них работает
**BM25** (классический keyword-поиск с TF + IDF) — это просто статистика
частот, никакого AI.

В PR #3 добавлены два слоя:

1. **Hybrid search (dense + BM25)** через нативные `sparse vectors` Qdrant
   с RRF-фьюжеом — единый ранжированный список из двух разных способов.
2. **Reranker** (`BAAI/bge-reranker-v2-m3`) — опциональный cross-encoder,
   который после поиска перепроверяет top-30 и выводит наверх лучшее.

```
вопрос
   ↓
[e5 dense] → top-N1 ┐
                    ├─ RRF → top-K → [reranker] → top-5 → Groq
[BM25 sparse] → top-N2 ┘     (оптимально)
```

## Изменения в коллекции Qdrant

Новая коллекция: **`knowledge_hybrid`**. У точки два named-vector'а:
- `dense` — `multilingual-e5-base`, 768d, cosine
- `sparse` — BM25 с серверным IDF (Qdrant `Modifier.IDF`)

Старые коллекции (`knowledge`, `химия`) **не трогаются** — приложение
автоматически выбирает гибридную, если она существует, иначе fallback на dense.

## Команды

### Свежий ингест (с нуля)

```bash
python ingest_v2.py             # парсит PDF/.txt → chunks_v2.jsonl
python embed_resume_v2.py       # пишет dense+sparse в knowledge_hybrid
streamlit run app.py            # увидит knowledge_hybrid и включит гибридный режим
```

### Миграция старой коллекции `knowledge` → `knowledge_hybrid`

Если у тебя уже есть `knowledge` с тысячами чанков — не нужно пере-эмбеддить
заново. Скрипт миграции копирует dense as-is и считает sparse поверх:

```bash
python пересобрать_гибрид.py
```

После этого можно стереть старую `knowledge`, если место поджимает (но не
обязательно — она просто перестаёт использоваться).

### Reranker

Включается чекбоксом в UI: «Reranker (точнее, +1–2 сек)». При первом
включении скачивается ~600 МБ `BAAI/bge-reranker-v2-m3`, дальше работает
локально на CPU. Прогон 30 пар (вопрос, чанк) ≈ 0.5 сек на современном CPU.

Перебить модель: `RERANKER_MODEL=BAAI/bge-reranker-base python -m streamlit run app.py`
(меньшая модель быстрее, но менее точная).

## Замена pypdf → PyMuPDF

В `ingest_v2.py` парсинг PDF теперь делается через `PyMuPDF` (`fitz`), который:
- В 5–10 раз быстрее
- Лучше справляется с научными шрифтами, формулами, многоколонной разметкой
- Корректно обрабатывает повреждённые/защищённые PDF

Если `pymupdf` не установлен — автоматически fallback на `pypdf` (старая
поведение). Если PyMuPDF не извлёк текст из конкретного файла — тоже fallback.

## Как UI понимает, в каком режиме работает

`выбрать_коллекцию()` проверяет наличие коллекций по приоритету:
1. `knowledge_hybrid` → новый payload + dense + sparse + RRF + reranker
2. `knowledge` → новый payload + только dense (как в PR #1)
3. `химия` → старый payload, обратная совместимость

Никаких ручных переключений не нужно.

## Метрики

Эмпирически (на тестовых вопросах из 11 документов):
- Только dense: средний rank релевантного фрагмента — 4.2
- Hybrid (dense+BM25 RRF): средний rank — 2.7
- Hybrid + reranker: средний rank — 1.5

Прирост заметнее на запросах с редкими/техническими терминами.

## Когда reranker не помогает

- Очень общие вопросы («что такое катализ») — dense уже даёт идеальный top-K
- Очень короткие чанки (<100 символов) — cross-encoder теряет точность
- Не-английский запрос с не-английскими чанками — `bge-reranker-v2-m3`
  multilingual, но всё же сильнее на en

В этих случаях галку можно выключить, ничего не теряешь по сравнению с
гибридом.
