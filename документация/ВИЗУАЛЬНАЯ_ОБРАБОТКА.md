# Визуальная обработка PDF в тетрадях

## Зачем

Глобальная база (`knowledge_hybrid`) — десятки тысяч PDF, парсинг текстовый,
дешёвый и быстрый. **Тетради** (`notebooks.py`) — это маленькие пользовательские
коллекции (~10 файлов), куда попадают конспекты, лекции, скан-материалы.

Часть таких файлов — сканы или PDF со схемами/графиками, где `PyMuPDF`
извлекает мало или ничего. Чтобы их всё-таки можно было искать, при загрузке
в тетрадь можно включить **визуальную обработку**.

## Архитектура

```
PDF → PyMuPDF text         (Tier 0 — всегда)
   → если мало текста:
        RapidOCR           (Tier 1 — локально, бесплатно)
   → если всё ещё мало и опция включена:
        Groq Vision        (Tier 2 — платно, ~$0.0004 за стр.)
   → склейка text + ocr + caption в один чанк
   → embedding (e5)
   → отдельная per-notebook коллекция Qdrant
```

Все Groq-вызовы — только **во время загрузки в тетрадь**, не в момент вопроса.
Когда пользователь задаёт вопрос, Groq получает только готовые текстовые
фрагменты (как и раньше).

## Кэш и бюджет

Каждая обработанная страница кэшируется глобально по `page_hash` (SHA-256
от рендера 200 dpi). Если та же страница встречается в другой тетради — она
не обрабатывается заново.

```
visual_index/
  pages/<page_hash>.json    — OCR + caption + tier_used
  images/<file_hash>/page_*.png  — рендеры страниц
  budget.json               — суммарный счётчик Groq Vision
```

Бюджет Groq Vision виден в UI при включённом тоггле:
> Всего вызвано Groq Vision: 17 стр., оценка стоимости ~$0.0072

Жёсткий потолок per-file задаётся переменной окружения
`NOTEBOOK_VISION_MAX_PAGES` (по умолчанию 30).

## Как включить

Вкладка «Мои документы» → выбрать тетрадь → отметить:

1. **«Распознавать сканы и схемы»** — включает Tier 0 + 1 (RapidOCR).
   Локально, бесплатно.
2. **«Дополнительно описывать графики/схемы через Groq Vision»** — включает
   Tier 2. Только для страниц, которые после Tier 1 всё ещё пустые.
   Требует `GROQ_API_KEY` в `.env`.

Оба тоггла per-upload — не сохраняются между загрузками, чтобы случайно не
влетать в платный режим.

## Что попадает в чанк

При визуальном режиме `text` чанка собирается из секций:

```
{native PyMuPDF text}

[OCR]
{rapidocr text}

[Описание изображения]
{groq vision caption}
```

Те же поля сохраняются раздельно в payload Qdrant: `tier_used`,
`has_ocr`, `has_visual_caption`, `page_hash`, `page_image_path`.

## Используемые модели

- **OCR**: `rapidocr-onnxruntime` — multi-lingual, CPU-only, без системных
  зависимостей (вместо Tesseract).
- **Vision**: `meta-llama/llama-4-scout-17b-16e-instruct` через Groq API
  ($0.11 input / $0.34 output за 1M токенов, 5 картинок на запрос).

## Стоимость в цифрах

- 1 страница рендера (~200 dpi PNG, base64) ≈ 1500–3000 input-токенов
  + ~200 токенов на caption ≈ **~$0.0004** за страницу.
- Тетрадь из 10 PDF, где у 5 страниц нужен Vision → **~$0.002** за тетрадь.
- 100 тетрадей с такой нагрузкой → ~$0.20.

Без Vision (только OCR) — бесплатно вообще.

## Когда Tier 2 НЕ зовётся

- Если Tier 0 + Tier 1 уже дали ≥ 30 слов на странице.
- Если страница уже есть в `visual_index/pages/`.
- Если в текущей загрузке исчерпан лимит `NOTEBOOK_VISION_MAX_PAGES`.
- Если `GROQ_API_KEY` пуст или тоггл выключен.

## Локальный запуск

```bash
pip install -r requirements.txt
# Первый запуск RapidOCR скачает модели (~50 МБ) в ~/.cache/rapidocr-onnxruntime/
python -m streamlit run app.py
```

## Что НЕ изменилось

- Глобальный `ingest_v2.py` / `embed_resume_v2.py` — без изменений.
  Корпус как был текстовым, так и остался.
- `app.py` answer pipeline — без изменений. Groq в момент вопроса видит
  только текст из payload (с пометками `[OCR]` / `[Описание изображения]`,
  если они там есть).
- Поиск по тетрадям — тот же per-notebook dense (не sparse).
