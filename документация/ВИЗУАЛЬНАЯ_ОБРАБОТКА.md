# Визуальная обработка

## Обзор

Модуль `core/визуальная_обработка.py` отвечает за OCR и обработку страниц PDF для пользовательских тетрадей. Используется когда PyMuPDF не может извлечь текст (сканы, рукописные заметки, фотографии конспектов).

---

## Три уровня обработки (Tiers)

| Tier | Метод | Стоимость | Скорость | Качество |
|------|-------|-----------|----------|----------|
| 0 | PyMuPDF text extraction | бесплатно | мгновенно | высокое (для текстовых PDF) |
| 1 | RapidOCR по рендеру страницы (200 DPI) | бесплатно | ~1-3 сек/стр | среднее (печатный текст) |
| 2 | Groq Vision caption (`llama-4-scout-17b-16e-instruct`) | ~$0.0004/стр | ~2-5 сек/стр | высокое (рукопись, схемы) |

### Логика выбора tier:

```
Страница PDF
  │
  ├── PyMuPDF text → ≥ 30 слов? → Tier 0 (готово)
  │
  ├── Нет → RapidOCR (рендер 200 DPI → PNG → OCR) → ≥ 30 слов? → Tier 1 (готово)
  │
  └── Нет → Groq Vision (если API-ключ есть и бюджет не исчерпан) → Tier 2
```

Порог «достаточно слов»: `MIN_WORDS_GOOD = 30` (слово = ≥ 2 символа).

### Vision-промпт (Tier 2)

```
"Опиши содержимое этой страницы документа на русском языке.
 Если есть графики, таблицы, схемы или формулы — опиши их суть.
 Будь кратким (3–5 предложений)."
```

Модель: `meta-llama/llama-4-scout-17b-16e-instruct` (через Groq API).

## Кэширование

Каждая обработанная страница кэшируется по `page_hash` (SHA-256 от **байтов рендера** страницы, а не самого PDF):

```
visual_index/pages/<page_hash>.json
```

Содержимое кэш-файла: text, ocr_text, visual_caption, tier_used, confidence.

Повторная обработка того же PDF мгновенна — результаты берутся из кэша. Одинаковые страницы из разных PDF/тетрадей тоже попадают в один кэш-запись.

---

## Бюджет Groq Vision (Tier 2)

Файл `visual_index/budget.json`:

```json
{
  "total_pages": 15,
  "last_reset": "2024-05-20T12:00:00Z"
}
```

- Лимит по умолчанию: `MAX_GROQ_PAGES_DEFAULT = 30` (env: `NOTEBOOK_VISION_MAX_PAGES`)
- Каждый вызов Tier 2 увеличивает `total_pages`
- При `total_pages ≥ MAX_GROQ_PAGES_DEFAULT` Tier 2 пропускается — остаётся на Tier 1

## Dataclass результата

```python
@dataclass
class СтраницаВизуал:
    page_number: int      # Номер страницы (1-based)
    text: str = ""        # Финальный текст (лучший из tier'ов)
    ocr_text: str = ""    # Результат RapidOCR (Tier 1)
    visual_caption: str = ""  # Результат Groq Vision (Tier 2)
    tier_used: int = 0    # Какой tier дал финальный результат (0/1/2)
    page_hash: str = ""   # SHA-256 рендера (ключ кэша)
    image_path: str = ""  # Путь к PNG рендеру страницы
    confidence: float = 0.0  # Уверенность OCR (0.0–1.0)
```

## Модуль извлечения картинок (`core/извлечение_картинок.py`)

Извлекает изображения из PDF-страниц для двух пайплайнов:
- `pipeline/ingest_v2.py` — массовый ингест корпуса
- `core/notebooks.py` — загрузка пользовательских документов

### Фильтрация декоративных

Декоративные изображения отбрасываются:
- Размер < **40px** по любой стороне (иконки, пиктограммы)
- Соотношение сторон > 10:1 (полоски, линии, разделители)
- Повторяющиеся фоновые xref (шаблоны журналов — детектируются через `найти_фоновые_xref()`)
- Логотипы издательств (по повторяющемуся хэшу xref на ≥50% страниц)

### Привязка подписей (caption binding)

Алгоритм:
1. Извлечение подписей со страницы — regex-паттерны: `Fig.`, `Figure`, `Рис.`, `Scheme`, `Table`, `Табл.`
2. Для каждой подписи вычисляется bbox (координаты на странице)
3. Для каждой картинки ищется **ближайшая подпись ниже** по bbox proximity (расстояние между нижним краем картинки и верхним краем подписи)
4. Если подпись ≤ 50px ниже картинки → привязывается как caption

Fallback: если подписей нет, но есть заголовок слайда (PPTX-конвертированные PDF) — он используется как caption.

### OCR изображений (EasyOCR)

```python
from извлечение_картинок import _получить_easyocr_reader

reader = _получить_easyocr_reader()  # ленивая загрузка, один раз
результаты = reader.readtext(image, detail=0, paragraph=True)
```

- EasyOCR загружается один раз, кэшируется в модуле
- Используется для распознавания текста на схемах и диаграммах
- Результат обрезается до 400 символов
- Если EasyOCR не установлен — функционал молча отключается


## Константы и ENV

| Параметр | Значение | Описание |
|----------|----------|----------|
| `RENDER_DPI` | 200 | DPI рендера страницы для OCR |
| `MIN_WORDS_GOOD` | 30 | Порог «достаточно текста» |
| `VISION_MODEL` | `meta-llama/llama-4-scout-17b-16e-instruct` | Модель Groq Vision |
| `MAX_GROQ_PAGES_DEFAULT` | 30 | Лимит страниц Tier 2 |
| `NOTEBOOK_VISION_MAX_PAGES` | env, default 30 | Переопределение лимита |
| `HARVEST_SKIP_IMAGES` | env, `0`/`1` | Пропуск картинок в CI-пайплайне |

## Зависимости

| Пакет | Назначение | Размер | Обязательный |
|-------|-----------|--------|-------------|
| `pymupdf` (fitz) | Рендер страниц в PNG, text extraction | ~30 MB | Да |
| `rapidocr-onnxruntime` | OCR Tier 1 (CPU, без системных зависимостей) | ~30 MB | Да |
| `easyocr` | OCR текста на изображениях | ~1 GB с моделями | Нет (опционально) |
| `pillow` | Обработка изображений | ~5 MB | Да |
| `opencv-python` | Декодирование изображений для EasyOCR | ~50 MB | Нет (вместе с easyocr) |
| `groq` | API для Vision caption (Tier 2) | ~1 MB | Да (для Tier 2) |
