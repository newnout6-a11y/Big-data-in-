# Структурированная мультидоменная БД

> Это PR #1: переход от плоской схемы `case` к иерархии `domain → subdomain` с
> авторазметкой через эмбеддинги, scope-guard, recency boost и базовым
> harvester'ом для автосбора корпуса.

## Что изменилось

### Таксономия (`taxonomy.py`)

Три домена, каждый с субдоменами:

- **`chemistry`** — organic, inorganic, physical, analytical, catalysis, materials, biochem_med, process_tech
- **`it_chem`** (пересечение) — cheminformatics, ml_for_chem, computational_chem, drug_discovery_ml, materials_informatics, lab_automation, text_mining_chem, ord_data
- **`it`** — ml_general, deep_learning, nlp, computer_vision, data_engineering, databases, software_engineering

Для каждого субдомена есть короткий **прототип-описание** на двух языках (RU+EN).

### Эмбеддинговый классификатор (`классификатор.py`)

Без LLM. Работает так:

1. Прототипы прогоняются через `multilingual-e5-base` → эталонные векторы (кэшируются в `prototype_cache.npz`).
2. Любой чанк/вопрос: `cos(вектор, прототипы)` → top-1 = `(domain, subdomain, score)`.
3. **Scope-guard**: если max(cos) < `SCOPE_ПОРОГ_ПО_УМОЛЧАНИЮ` (0.55) → off-topic, отказ с примерами вопросов в скоупе.

### Новая схема payload в Qdrant

Коллекция `knowledge` (старая `химия` остаётся для обратной совместимости).

```json
{
  "text": "...",
  "document": "...",
  "page": 5,
  "case": "катализ",                  // backward-compat
  "doc_id": "arxiv:2401.12345",
  "source": "arxiv|chemrxiv|openalex|local",
  "title": "...",
  "authors": ["Doe J.", "Smith A."],
  "year": 2024,
  "domain": "it_chem",
  "subdomain": "ml_for_chem",
  "topic_score": 0.71,
  "language": "en",
  "embed_model": "e5-base-v1",
  "text_hash": "sha1:...",
  "ingested_at": "2025-04-29"
}
```

Payload-индексы создаются автоматически по `domain, subdomain, source, language, doc_id, year, text_hash`.

### Recency boost

Финальный score = `cosine * (1 + λ * (exp(-(now-year)/15) - 1))`. λ настраивается в UI («Бонус свежести», 0.0–1.0). Свежие статьи всплывают выше при равной релевантности.

## Миграция: пошагово

### Сценарий 1. У тебя уже есть `qdrant_db/` со старой коллекцией `химия`

```bash
pip install -r requirements.txt
python миграция_в_v2.py    # перенесёт 46k точек в knowledge с новой разметкой
streamlit run app.py        # автоматически подхватит коллекцию knowledge
```

### Сценарий 2. С нуля + автосбор корпуса

```bash
pip install -r requirements.txt -r harvester/requirements.txt

# 1. Автосбор PDF (~300 за прогон, повторяй сколько нужно)
python -m harvester.run --budget 300 --year-min 2020 --email you@example.com

# 2. Парсинг и чанкинг
python ingest_v2.py

# 3. Векторизация в Qdrant
python embed_resume_v2.py

# 4. Запуск приложения
streamlit run app.py
```

### Сценарий 3. Гибрид

Сначала миграция существующих, потом докачка нового:

```bash
python миграция_в_v2.py
python -m harvester.run --budget 500 --email you@example.com
python ingest_v2.py    # обработает только новые файлы
python embed_resume_v2.py    # инкрементально докинет
```

## Настройки

- **Порог scope-guard** — `SCOPE_ПОРОГ_ПО_УМОЛЧАНИЮ` в `классификатор.py`. Если получаешь много false-positive (in-scope вопросы режутся) — снизь до 0.50. Если много false-negative (off-topic просачивается) — подними до 0.60.
- **Свежесть** — λ в `app._recency_boost` (по умолчанию 0.0667 ≈ хвост exp 15 лет). Слайдер в UI «Бонус свежести» масштабирует эффект от 0 до 1.
