# Архитектура проекта — техническая глубина

## Обзор

Проект «Навигатор цифровой химии» — полный RAG-пайплайн:

```
Источники (8 API) → PDF/TXT → Чанки (800 сим) → Qdrant (dense+sparse) → Гибридный поиск → Reranker → LLM → UI
```

Ниже — не абстрактные диаграммы, а конкретные алгоритмы, параметры и решения из кода.

---

## 1. Харвестер (`harvester/run.py`)

### Источники и курсоры

| Источник | API | Тип курсора | Примечания |
|----------|-----|-------------|------------|
| arXiv | OAI-PMH / atom | `last_index` (int) | cs.LG, physics.chem-ph |
| ChemRxiv | JSON REST | `skip` (int) | CF может блокировать CI-IP |
| OpenAlex | REST + cursor | `cursors: {concept_id: "*"}` | 5 концептов, делит бюджет поровну |
| Europe PMC | REST + cursor | `cursors: {query: "*"}` | Полнотекстовый доступ |
| КиберЛенинка | OAI-PMH | `current_date` (YYYY-MM-DD) | Сдвиг по 1 дню за прогон |
| Stack Exchange | REST API | `sites: {site: page}` | Q + top answer как .txt |
| Semantic Scholar | REST + offset | `offsets: {query: int}` | Требует SEMANTIC_SCHOLAR_API_KEY |
| CORE | REST + offset | `offsets: {query: int}` | Требует CORE_API_KEY |

### Топик-балансировка бюджетов

Проблема: без контроля один домен (IT или химия) забьёт корпус на 80%.

Решение (`harvester/домены.py`):
- Каждый скачанный документ классифицируется в `chem` / `it` / `other` по keyword-маркерам в title+abstract
- `state.json` хранит `domain_counts: {chem: N, it: M, other: K}`
- При запуске вычисляются мультипликаторы бюджета:

```python
# Идеальное распределение: 45% chem, 45% it, 10% other
raw = target_ratio / actual_ratio
коэф = clamp(sqrt(raw), 0.25, 2.5)   # мягкий корректор
```

- Если `domain_counts` < 50 документов — все коэф = 1.0 (стартовая фаза, нет смысла корректировать)
- Каждый источник привязан к ожидаемому домену: `arxiv → it`, `chemrxiv → chem`, `europepmc → chem`
- Бюджет источника = `общий_бюджет * вес_источника / сумма_весов`

### Кросс-источниковый дедуп (`harvester/state.py`)

Один и тот же документ приходит из разных источников (arxiv, OpenAlex, Semantic Scholar). Нормализация `doc_id` → единый ключ:

```
arxiv:2304.12345v2                    → arxiv:2304.12345     (убрать vN)
openalex:10.48550/arXiv.2304.12345    → arxiv:2304.12345     (распознать arxiv-DOI)
europepmc:10.1038/s41586-023-12345    → doi:10.1038/s41586-023-12345
europepmc:PMC1234567                  → pmc:pmc1234567
se:stackoverflow:12345                → se:stackoverflow:12345 (as-is)
```

Приоритет разбора: arxiv-DOI → arxiv-new → arxiv-old → обычный DOI → PMC → fallback lowercase.

Структура state в памяти:
- `downloaded_ids: list` — сериализуется в JSON
- `normalized_ids: list` — сериализуется в JSON
- `_downloaded_set: set` — runtime-only O(1) lookup, не попадает в JSON
- `_normalized_set: set` — runtime-only O(1) lookup

Сохранение — атомарное: запись во `.tmp`, затем `os.replace()`.

### Unpaywall fallback

Если прямая ссылка на PDF не работает (paywall), харвестер:
1. Извлекает DOI из `doc_id` регексом `10.\d{4,9}/[^\s]+`
2. Запрашивает Unpaywall API с email
3. Если найдена OA-копия — скачивает с альтернативного URL

### HTTP-клиент

```python
httpx.Client(timeout=120, headers={
    "User-Agent": "Mozilla/5.0 (Windows NT 10.0; ...) Chrome/120.0.0.0",
    "Accept": "application/pdf,*/*;q=0.8",

```


## 2. Ингест (`pipeline/ingest_v2.py`)

### Пайплайн обработки одного файла

```
PDF/DOCX/TXT
    │
    ├── PyMuPDF (основной) → fallback pypdf (если PyMuPDF ничего не извлёк)
    │   Порог: > 50 символов на страницу, иначе страница пропускается
    │
    ├── Фильтр качества (3 критерия, см. ниже) → rejected_pdfs/
    │
    ├── Извлечение изображений (HARVEST_SKIP_IMAGES=1 — отключает)
    │   - Фильтр декоративных (< 80px, полоски, логотипы)
    │   - Привязка подписей (Fig./Рис./Scheme/Table) по bbox proximity
    │   - Детекция повторяющихся фонов → фоновые_xref
    │
    ├── Разбиение на чанки
    │   размер = 800 символов, перекрытие = 100
    │   Алгоритм: скользящее окно с шагом (размер - перекрытие) = 700 символов
    │   Минимальный чанк: > 80 символов (иначе отбрасывается)
    │
    ├── Дедупликация внутри сессии
    │   SHA-1(text) → если хэш уже встречался в текущем запуске → skip
    │
    ├── Авторазметка батчем (core/классификатор.py)
    │   Модель sentence-transformers загружается один раз
    │   Батч = 64 чанка → encode → cosine с прототипами → (домен, субдомен, score)
    │
    ├── Определение языка
    │   доля кириллицы > 50% → "ru"
    │   доля кириллицы < 5% → "en"
    │   иначе → "mixed"
    │
    └── Обогащение метаданными из harvested_meta/<имя>.json
        doc_id, источник, название, авторы, дата → год
```

### Фильтр качества (`core/фильтр_качества.py`)

| Критерий | Порог по умолчанию | Env-переменная | Применяется |
|----------|-------------------|----------------|-------------|
| Минимум слов в файле | 200 | `QUALITY_MIN_WORDS` | Всегда |
| Символов на страницу | 300 | `QUALITY_MIN_CHARS_PER_PAGE` | PDF ≥ 3 стр |
| Доля непустых страниц | 30% | `QUALITY_MIN_NONEMPTY_FRAC` | PDF ≥ 3 стр |

Непустая страница = ≥ 100 символов. Отбракованные перемещаются (не удаляются) в `rejected_pdfs/` с файлом `<имя>.reason.txt`.

### Инкрементальность

- По умолчанию: `собрать_обработанные()` сканирует `chunks_v2.jsonl`, собирает set имён файлов → пропускает уже обработанные
- `--full`: перезаписывает `chunks_v2.jsonl` с нуля

## 3. Векторизация (`pipeline/embed_resume_v2.py`)

### Конфигурация коллекции Qdrant

```python
collection_name = "knowledge_hybrid"
vectors_config = {
    "dense": VectorParams(size=768, distance=COSINE, on_disk=True)
}
sparse_vectors_config = {
    "sparse": SparseVectorParams(index=SparseIndexParams(on_disk=True), modifier=IDF)
}
quantization_config = BinaryQuantization(always_ram=True)
```

**Зачем `on_disk=True` + `BinaryQuantization(always_ram=True)`:**
- Оригинальные 768-мерные float32 лежат на диске (не влезут в 1 GB RAM Qdrant Cloud Free)
- В RAM живут только бинарные коды (768 бит = 96 байт на точку vs 3072 байт без квантования) — 32x экономия
- При поиске сначала грубый поиск по бинарным кодам, затем rescore по полным векторам с диска для top-K
- Потеря recall: 2–5%, компенсируется cross-encoder reranker

### Идемпотентность

```python
ID точки = uuid5(NAMESPACE_URL, text_hash)
```

Один и тот же текст всегда получает один UUID → повторный `upsert` = no-op. Перезапуск после падения безопасен.

### Resume-механизм

1. При старте: `scroll()` всей коллекции по батчам 512, собирает `set(text_hash)` существующих точек
2. Фильтрует `chunks_v2.jsonl` — оставляет только чанки с `text_hash ∉ existing`
3. Грузит батчами по 64:
   - Dense: `model.encode(["passage: " + text], normalize=True)` → 768d float32
   - Sparse: `FastEmbed("Qdrant/bm25").embed(texts)` → (indices, values)
   - `upsert(points)` с полным payload

### Payload-индексы

Автоматически создаются при первом запуске:
```
domain      → KEYWORD (фильтрация в UI)
subdomain   → KEYWORD
source      → KEYWORD
language    → KEYWORD
doc_id      → KEYWORD
year        → INTEGER (range-фильтрация)
text_hash   → KEYWORD (дедуп при resume)
```

### Подключение

```python
else:
    QdrantClient(path="qdrant_db/")  # встроенный локальный
```

## 4. Гибридный поиск (`core/hybrid_search.py`)

### RRF Fusion — формула

```python
def rrf_fuse(списки_id, k=60):
    """Reciprocal Rank Fusion."""
    для каждого списка:
        для каждого (ранг, id):
            score[id] += 1 / (k + ранг + 1)
    return sorted by score desc
```

- `k=60` — стандартное значение из оригинальной RRF-статьи (Cormack et al. 2009)
- Чем меньше `k`, тем больше вес верхних позиций; при `k=60` баланс между top-тяжёлым и flat

### BM25 sparse — не нейросеть

```python
from fastembed import SparseTextEmbedding
model = SparseTextEmbedding(model_name="Qdrant/bm25")  # ~25 KB словарь
```

Это **не** нейросеть — просто BM25 токенизация + TF-веса. IDF вычисляется на стороне Qdrant (параметр `modifier=IDF` в коллекции). FastEmbed даёт только `(indices, values)` для TF-части.

### Ленивая загрузка (thread-safe)

```python
_замок_bm25 = threading.Lock()
_кэш_bm25 = {}

def получить_bm25():
    if "model" in _кэш_bm25:           # fast path, без блокировки
        return _кэш_bm25["model"]
    with _замок_bm25:                    # double-checked locking
        if "model" in _кэш_bm25:
            return _кэш_bm25["model"]
        _кэш_bm25["model"] = SparseTextEmbedding("Qdrant/bm25")
        return _кэш_bm25["model"]
```

Один и тот же паттерн используется для reranker и эмбеддинг-модели.

## 5. Cross-encoder Reranker (`core/reranker.py`)

### Характеристики

| Параметр | Значение |
|----------|----------|
| Модель | `BAAI/bge-reranker-v2-m3` (env: `RERANKER_MODEL`) |
| Размер | ~600 MB |
| max_length | 512 токенов |
| Устройство | CPU |
| Скорость | ~0.5 сек на 30 пар (вопрос, чанк) |

### Алгоритм

```python
пары = [(вопрос, документ) for документ in top_30_документов]
скоры = CrossEncoder.predict(пары)  # float для каждой пары
результат = sorted(enumerate(скоры), key=lambda: -score)[:top_k]
```

Reranker видит **и вопрос, и документ целиком** (а не только эмбеддинг) → понимает семантику пересечения лучше, чем cosine. Компенсирует потерю recall от binary quantization.

## 6. Scope-guard (`core/классификатор.py`)

### Двухуровневый механизм

```
Вопрос
  │
  ├── encode("query: " + вопрос) → вектор 768d
  │
  ├── pos_scores = прототипы_субдоменов @ вектор    (cosine, т.к. оба normalized)
  ├── neg_scores = отрицательные_якоря @ вектор
  │
  ├── ПРОВЕРКА 1: max(pos_scores) ≥ 0.50?
  │   НЕТ → off-topic (абракадабра, бессмыслица)
  │
  └── ПРОВЕРКА 2: max(pos) - max(neg) ≥ 0.0?
      НЕТ → off-topic (ближе к спорту/кулинарии/etc)
      ДА  → in-scope → (домен, субдомен, score)
```

### Почему margin, а не порог?

Multilingual-e5 даёт неинформативно высокие cosine (~0.7) на **любую** пару текстов. Абсолютный порог бесполезен для большинства случаев. Margin `(best_positive - best_negative)` показывает, к чему вопрос **ближе** — к нашей теме или к off-topic якорям.

### 8 отрицательных якорей

```
Спорт | Кулинария | Путешествия | Литература/искусство |
Быт/покупки | Политика | История/география | Развлечения/игры
```

### Кэширование прототипов

- Эмбеддинги прототипов + негативов сохраняются в `prototype_cache.npz`
- Ключ кэша = SHA-1 всех текстов прототипов + негативов
- Пересчёт только если изменилась таксономия (добавлен домен/субдомен) или якоря

## 7. Таксономия (`core/taxonomy.py`)

Иерархия из 3 корневых доменов:

```
chemistry (8 субдоменов):
  organic, inorganic, physical, analytical, catalysis,
  materials, biochem_med, process_tech

it_chem (8 субдоменов, пересечение):
  cheminformatics, ml_for_chem, computational_chem,
  drug_discovery_ml, data_chem, materials_informatics,
  process_chemometrics, nlp_chem

it_ml (5 субдоменов, общий IT):
  ml_general, nlp_general, cv_general,
  data_engineering, optimization
```

Каждый субдомен имеет **текст-прототип** на ru+en (1–3 предложения). Классификатор работает **без LLM** — только cosine similarity эмбеддинга текста vs эмбеддингов прототипов.

### Пакетная классификация при ингесте

```python
# Батч по 64 чанка → encode → матричное умножение (64, 768) @ (768, N_прототипов)
скоры = векторы @ прототипы.T    # → (64, 21) матрица
индексы = argmax(скоры, axis=1)  # → лучший субдомен для каждого чанка
```

Скорость: ~500 чанков/сек на CPU (узкое место — encode, не argmax).

## 8. Генерация ответа (LLM)

### Системный промпт — ключевые правила

| # | Правило | Зачем |
|---|---------|-------|
| 1 | Отвечать ТОЛЬКО на русском | Корпус смешанный ru/en, ответ единообразный |
| 2 | Только факты из CONTEXT | Запрет галлюцинаций |
| 3 | Если есть хоть частичная инфо — развёрнутый ответ | Уменьшает false refusals |
| 4 | [N] — не библиография, а наши метки | LLM часто путает маркеры с references |
| 7 | Маркер [N] на каждое утверждение | Обязательное цитирование |
| 9 | Формулы в `$$...$$` блочные, `$...$` только переменные | KaTeX рендеринг |
| 10 | Запрет формул НЕ из CONTEXT | Запрет галлюцинированных уравнений |
| 11 | Максимум 2 картинки `[img:N.M]` | Не засорять ответ |

### Модели

| Приоритет | Модель | Контекст | Скорость |
|-----------|--------|----------|----------|
| Основная | `llama-3.3-70b-versatile` | 128K | ~30 tok/s |
| Fallback | `llama-3.1-8b-instant` | 128K | ~100 tok/s |

Fallback срабатывает при rate-limit или ошибке основной модели.

### Пост-обработка ответа

1. **Чистка PDF cmap-артефактов**: `¼`→`=`, `þ`→`+`, лигатуры `ﬁ`→`fi`
2. **Фильтр мусорных фрагментов**: чистые библиографии, колонтитулы, оглавления
3. **Валидация маркеров [N]**: embedding post-check (cosine similarity утверждения vs фрагмент N)
4. **LaTeX cleanup**: вынос маркеров `[N]` из внутренностей `$$...$$`
5. **Вставка изображений**: маркеры `[img:N.M]` → реальные пути из payload

## 9. UI (`ui/app.py`)

### Streamlit State Management

Ключевые `st.session_state`:
- Модель и клиенты загружаются лениво, хранятся в session_state
- `TRANSFORMERS_NO_TF=1`, `USE_TF=0` — отключают TensorFlow (не нужен, только PyTorch)

### Вкладки

| Вкладка | Модуль | Функциональность |
|---------|--------|-----------------|
| Поиск | `app.py` + `hybrid_search` | RAG Q&A с цитатами |
| Мои документы | `core/notebooks.py` | Upload → OCR → поиск внутри |
| Учёба | `core/study_tools.py` | Конспекты, карточки, квизы, графы |
| Кейсы | `core/cases.py` | 15 тематических маршрутов |
| Архитектура | `app.py` | Визуализация структуры системы |

### Пользовательские тетради (`core/notebooks.py`)

- Каждая тетрадь = отдельная коллекция Qdrant `notebook_<uuid>`
- OCR: трёхуровневый — Tier 0 (PyMuPDF text) → Tier 1 (RapidOCR) → Tier 2 (Groq Vision)
- Поиск внутри тетради с keyword-бустом

## 12. Потокобезопасность и ленивая инициализация

Все тяжёлые модели загружаются один раз с double-checked locking:

```python
_замок = threading.Lock()
_кэш = {}

def получить():
    if "m" in _кэш:        # Hot path: без lock
        return _кэш["m"]
    with _замок:            # Cold path: загрузка
        if "m" in _кэш:    # Double-check
            return _кэш["m"]
        _кэш["m"] = загрузить_модель()
        return _кэш["m"]
```

Применяется для: BM25 (~25 KB), Reranker (~600 MB), SentenceTransformer (~440 MB).

## 13. Принятые компромиссы

| Решение | Плюс | Минус |
|---------|------|-------|
| Binary quantization | 32x RAM, 3-5M точек в 1 GB | -2-5% recall |
| Reranker поверх binary | Восстанавливает recall | +0.5 сек latency |
| BM25 через FastEmbed | Нет отдельного Elasticsearch | IDF считается только по коллекции |
| Scope-guard без LLM | 0 API-вызовов, мгновенно | Ошибки на пограничных запросах |
| Чанки 800/100 символов | Влезает в контекст reranker (512 tok) | Может разрезать формулу |
| PyMuPDF + pypdf fallback | 99% покрытие PDF | pypdf медленнее в 5-10x |
| Groq бесплатный tier | $0 за LLM | Rate limits, нет fine-tuning |
