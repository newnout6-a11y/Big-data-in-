# Архитектура проекта

## Обзор

Проект «Навигатор цифровой химии» — это RAG-система с полным пайплайном:
сбор документов → ингест → векторизация → поиск → генерация ответа.

---

## Слои системы

### 1. Сбор данных (harvester/)

```
harvester/run.py  →  all_pdfs/ + harvested_meta/
```

Оркестратор обходит 8 источников (arXiv, OpenAlex, Europe PMC, Semantic Scholar, ChemRxiv, КиберЛенинка, Stack Exchange, CORE), скачивает PDF/TXT и сохраняет метаданные (DOI, авторы, дата, категории). Состояние хранится в `harvester/state.json` с инкрементальными курсорами.

### 2. Ингест (pipeline/ingest_v2.py)

```
all_pdfs/ + harvested_meta/  →  chunks_v2.jsonl
```

Для каждого файла:
1. Извлечение текста: PyMuPDF (основной) + PyPDF (fallback)
2. Фильтр качества: отбраковка пустых/повреждённых PDF → `rejected_pdfs/`
3. Разбиение на чанки: 800 символов, перекрытие 100
4. Дедупликация: SHA-1 text_hash
5. Авторазметка: домен/субдомен через эмбеддинговый классификатор (без LLM)
6. Определение языка: ru/en/other
7. Извлечение изображений: фильтр декоративных, привязка подписей, OCR
8. Обогащение метаданными из `harvested_meta/<hash>.json`

Формат записи в `chunks_v2.jsonl`:
```json
{
  "text": "текст чанка",
  "document": "имя_файла.pdf",
  "page": 5,
  "images": [{"path": "extracted_images/<hash>/img_5_0.png", "caption": "..."}],
  "doc_id": "arxiv:2301.12345",
  "source": "arxiv",
  "title": "Название статьи",
  "authors": ["Автор А.", "Автор Б."],
  "year": 2024,
  "domain": "cheminformatics",
  "subdomain": "molecular_descriptors",
  "topic_score": 0.847,
  "language": "en",
  "embed_model": "multilingual-e5-base",
  "text_hash": "a1b2c3d4e5...",
  "ingested_at": "2024-05-20"
}
```

### 3. Векторизация (pipeline/embed_resume_v2.py)

```
chunks_v2.jsonl  →  Qdrant (коллекция knowledge_hybrid)
```

- **Dense vector**: `intfloat/multilingual-e5-base`, 768 измерений, cosine
- **Sparse vector**: BM25 с серверным IDF (через `Qdrant/bm25` FastEmbed)
- **Binary quantization**: 32x экономия RAM, recall -2-5%
- **Идемпотентность**: ID = UUIDv5(text_hash)

Payload-индексы: `domain`, `subdomain`, `source`, `language`, `doc_id`, `year`, `text_hash`.

### 4. Поиск (core/hybrid_search.py + ui/app.py)

При получении вопроса:
1. Scope-guard: классификатор проверяет, относится ли вопрос к теме
2. Dense-поиск: `query: <вопрос>` → e5 → cosine similarity
3. Sparse-поиск: BM25 токенизация → exact match
4. RRF fusion: объединение двух списков через Reciprocal Rank Fusion
5. Фильтры: по домену, языку, году (опционально из UI)
6. Reranker: cross-encoder `BAAI/bge-reranker-v2-m3` переранжирует top-30
7. Recency boost: свежие документы получают бонус к скору

### 5. Генерация ответа (ui/app.py → Groq)

1. Top-K фрагментов → системный промпт с правилами цитирования
2. Groq API: `llama-3.3-70b-versatile` (fallback: `llama-3.1-8b-instant`)
3. Пост-обработка ответа:
   - Чистка PDF cmap-артефактов (`¼`→`=`, `þ`→`+`, лигатуры)
   - Фильтр мусорных фрагментов (библиографии, колонтитулы)
   - Embedding пост-проверка маркеров `[N]` (cos-sim)
   - Вынос маркеров из LaTeX-блоков `$$...$$`
   - Вставка изображений по маркерам `[img:N.M]`
4. Рендеринг: интерактивные цитаты с тултипами, LaTeX через KaTeX

### 6. Пользовательские тетради (core/notebooks.py)

Отдельная подсистема для загрузки пользовательских документов:
- Поддержка: PDF, DOCX, PPTX, TXT
- Индексация в отдельные коллекции Qdrant (`notebook_<uuid>`)
- OCR через визуальную обработку (Tier 0 → Tier 1 → Tier 2)
- Поиск внутри тетради с keyword-бустом

### 7. Учебные инструменты (core/study_tools.py)

Генерация учебных материалов на основе фрагментов тетради:
- **Конспекты**: тезисный пересказ лекции/главы через LLM
- **Флеш-карточки**: JSON → Anki APKG / TSV / CSV / DOCX
- **Квизы**: генерация вопросов с вариантами ответов
- **Графы связей**: Graphviz DOT → SVG визуализация

## Таксономия (core/taxonomy.py)

Иерархия доменов знаний — 3 корневых домена, каждый с субдоменами:

```
ДОМЕНЫ = {
  "chemistry": {                       # Химия
    "organic", "inorganic", "physical", "analytical",
    "catalysis", "materials", "biochem_med", "process_tech"
  },
  "it_chem": {                         # IT в химии (пересечение)
    "cheminformatics", "ml_for_chem", "computational_chem",
    "drug_discovery_ml", "data_chem", "materials_informatics",
    "process_chemometrics", "nlp_chem"
  },
  "it_ml": {                           # IT и ML (общие)
    "ml_general", "nlp_general", "cv_general",
    "data_engineering", "optimization"
  }
}
```

Каждый субдомен имеет текст-прототип на русском + английском. Классификатор (core/классификатор.py) эмбеддит прототипы один раз, затем для любого текста находит ближайший субдомен по cosine similarity. Прототипы кэшируются на диск (`prototype_cache.npz`) — пересчитываются только при изменении таксономии (SHA-1 хэш текстов прототипов).

## Классификатор и Scope-guard (core/классификатор.py)

- **Классификация**: текст → (домен, субдомен, score) — top-1 по cosine среди in-scope прототипов
- **Пакетная классификация**: `классифицировать_батч()` — батчевое кодирование для ингеста (по 64 чанка)
- **Scope-guard**: двухуровневый механизм отсечения off-topic вопросов:
  - `SCOPE_АБС_ПОРОГ = 0.50` — если max cos с любым in-scope прототипом ниже 0.50 → сразу off-topic
  - `SCOPE_MARGIN_ПОРОГ = 0.0` — если лучший off-scope прототип ближе или равен лучшему in-scope → off-topic
  - 8 отрицательных якорей (спорт, кулинария, путешествия, литература, быт, политика, история, развлечения) — их эмбеддинги служат «не наша область»
- Без LLM-вызовов — только sentence-transformers
- Потокобезопасность: double-checked locking для ленивой загрузки прототипов

## Тематические кейсы (core/cases.py)

15 предопределённых кейсов для маршрутизации вопросов в UI:

| Кейс | Ключевые слова |
|------|---------------|
| Поиск лекарственных молекул | drug discovery, SMILES, docking, фармакофор |
| Прогноз токсичности | toxicity, LD50, ADMET, QSAR |
| Оптимизация реакции | bayesian optimization, high-throughput |
| Прогноз выхода реакции | yield prediction, product yield |
| Подбор катализатора | catalyst, catalysis, TOF |
| Поиск новых материалов | perovskite, MOF, band gap |
| Прогноз свойств материала | GNN, thermal conductivity, hardness |
| Анализ спектров | NMR, IR, mass spectrometry |
| Контроль производства | soft sensor, process control, distillation |
| Прогноз поломок оборудования | predictive maintenance, anomaly detection |
| Оптимизация расхода энергии | heat exchanger, exergy, CO2 capture |
| Зелёная химия | green synthesis, atom economy, E-factor |
| Извлечение данных из статей | text mining, NER, DECIMER |
| База лабораторных экспериментов | ELN, FAIR, ORD |
| Связь с направлением ЦХТ | cheminformatics, digital chemistry, education |

Определение кейса — простое keyword matching (`определить_кейс()`): считает совпадения ключевых слов в тексте вопроса, выбирает кейс с максимумом. Без эмбеддингов, без LLM.

## Фильтр качества (core/фильтр_качества.py)

Отбраковка PDF до ингеста — не удаляет физически, перемещает в `rejected_pdfs/` с записью причины в `<имя>.reason.txt`.

Три критерия (пороги настраиваются через env):

| Критерий | По умолчанию | Env-переменная |
|----------|-------------|----------------|
| Минимум слов | 200 | `QUALITY_MIN_WORDS` |
| Минимум символов на страницу | 300 | `QUALITY_MIN_CHARS_PER_PAGE` |
| Минимум доля непустых страниц | 30% | `QUALITY_MIN_NONEMPTY_FRAC` |

Непустая страница = ≥100 символов. Критерии 2 и 3 применяются только для PDF с ≥3 страницами.

---

## Визуальная обработка (core/визуальная_обработка.py)

Три уровня обработки страниц PDF:

| Tier | Метод | Стоимость | Скорость |
|------|-------|-----------|----------|
| 0 | PyMuPDF text extraction | бесплатно | мгновенно |
| 1 | RapidOCR по рендеру страницы | бесплатно | ~1-3 сек/стр |
| 2 | Groq Vision caption | ~$0.0004/стр | ~2-5 сек/стр |

Результат кэшируется по `page_hash` (SHA-256). Бюджет Tier 2 контролируется через JSON-файл.

---

## Извлечение изображений (core/извлечение_картинок.py)

- Фильтр декоративных картинок (< 80px, полоски, логотипы)
- Детекция повторяющихся фоновых изображений (шаблоны)
- Привязка подписей к изображениям по bbox proximity
- OCR текста на изображениях (EasyOCR)
- Vision caption через Groq (опционально)

```
                    └──────┬───────┘
                           │ да

              ┌────────────────────────┐
              │   Гибридный поиск      │
              │  dense + sparse + RRF  │
              └────────────┬───────────┘
                           │ top-30
                           ▼
              ┌────────────────────────┐
              │   Cross-encoder        │
              │   reranker             │

                           │ top-K (отсортированы)

              ┌────────────────────────┐
              │   Фильтрация мусора    │

              └────────────┬───────────┘
                           │
                           ▼
              ┌────────────────────────┐
              │   Groq LLM             │
              │   (системный промпт    │

                           ▼
                    ┌──────────────┐
                    │    UI ответ   │

                    └──────────────┘
```
