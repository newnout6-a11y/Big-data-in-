# Учебные инструменты

## Обзор

Вкладка «Учёба» в UI предоставляет набор инструментов для генерации учебных материалов на основе загруженных документов. Вся логика — в `core/study_tools.py`, вызывается из `ui/app.py`.

---

## Архитектура модуля

```
core/study_tools.py
├── fragments_context()          # Сборка контекста из фрагментов (max 12000 символов)
├── parse_json_loose()           # Извлечение JSON из ответа LLM (с fallback)
├── markdown_export()            # Экспорт ответа в .md (с base64-картинками)
├── docx_export()                # Экспорт в .docx (LaTeX → OMML, встроенные картинки)
├── cards_to_tsv/csv()           # Карточки → TSV/CSV
├── cards_docx_export()          # Карточки → DOCX (для печати)
├── build_apkg()                 # Карточки → Anki APKG (через genanki)
├── save_flashcard_exports()     # Сохранение всех форматов карточек на диск
├── graphviz_dot()               # Граф связей → DOT-код
└── (внутренние)
    ├── _omath() / _math_fragments()   # LaTeX → Office Math XML (OMML)
    ├── _очистить_latex_вне_формул()   # Удаление \text{} вне $-блоков
    ├── _заменить_img_маркеры_на_markdown()  # [img:N.M] → ![](data:...)
    └── _docx_добавить_текстовый_блок/картинку()
```

## Функции

### 1. Конспекты

Генерация тезисного пересказа лекции или главы через LLM.

**Режимы:**
- **Вся лекция** — конспект всего документа целиком
- **Глава / тема** — конспект по выбранным страницам или теме

**Процесс:**
1. `fragments_context(fragments, max_chars=12000)` — собирает текстовый контекст из фрагментов тетради
2. Контекст → системный промпт + задание → Groq LLM
3. Ответ → Markdown с формулами, определениями, ключевыми тезисами

**Ограничение контекста:** `max_chars=12000` символов — если фрагментов больше, они обрезаются. Это даёт ~3000 токенов, оставляя место для ответа в рамках rate-limit Groq.

**Экспорт:**
- Markdown (`.md`) — с base64-встроенными картинками (файл самодостаточен)
- DOCX — формулы конвертируются в Office Math XML (OMML)

### 2. Флеш-карточки

Генерация карточек «вопрос — ответ» из содержимого документа.

**Процесс:**
1. LLM получает фрагменты и генерирует JSON-массив карточек
2. `parse_json_loose()` извлекает JSON даже при неидеальном ответе:
   - Убирает ```json``` обёртки
   - Ищет первый `{` и последний `}` если прямой parse упал
   - Если результат — list, оборачивает в `{"items": list}`
3. Карточки обогащаются источниками (номер страницы, документ)

**Форматы экспорта:**

| Формат | Функция | Описание | Особенности |
|--------|---------|----------|-------------|
| Anki APKG | `build_apkg()` | Готовый пакет для Anki | `genanki` library, стабильные ID из hash |
| TSV | `cards_to_tsv()` | Tab-separated | BOM UTF-8, импорт в Anki/Quizlet |
| CSV | `cards_to_csv()` | Comma-separated | BOM UTF-8, dialect excel |
| DOCX | `cards_docx_export()` | Для печати | Bold вопрос + обычный ответ |

### 3. Квизы

Генерация вопросов с вариантами ответов (multiple choice).

**Процесс:**
1. LLM генерирует JSON: `{"questions": [{"question": "...", "options": [...], "correct": 0}]}`
2. `parse_json_loose()` с fallback на regex
3. UI показывает интерактивный квиз: radio-кнопки, проверка, подсчёт правильных

### 4. Граф связей

Визуализация связей между понятиями в документе.

**Процесс:**
1. LLM извлекает ключевые понятия и связи: `{"nodes": [...], "edges": [{"from": ..., "to": ..., "label": ...}]}`
2. `graphviz_dot(graph)` строит DOT-описание:
   ```dot
   digraph G {
     rankdir=LR; node[shape=box,style=filled,fillcolor="#e3f2fd"];
     n0[label="Понятие А"];
     n1[label="Понятие Б"];
     n0 -> n1 [label="связь"];
   }
   ```
3. Рендеринг в SVG через Graphviz (если установлен) или `streamlit-agraph`

**Вспомогательные функции:**
- `_stable_int(seed)` — детерминистический int из строки (для ID узлов)
- `_dot_id(value)` — безопасный идентификатор для Graphviz (только `[a-zA-Z0-9_]`)
- `_clean_cell(value)` — очистка текста: trim, убрать переносы строк

## Экспорт ответов из RAG

Помимо учебных инструментов, основной ответ RAG тоже экспортируется:

### Markdown export

```python
markdown_export(title, body, fragments, image_resolver=..., embed_base64=True)
```

- Маркеры `[img:N.M]` → `![caption](data:image/png;base64,...)` (self-contained)
- LaTeX `$$...$$` и `$...$` — оставляются как есть (Obsidian/Typora/GitHub понимают)
- Голый `\text{...}` вне $-блоков → просто текст (чистка артефактов)
- Раздел "Источники" внизу: `[N] документ, стр. X`

### DOCX export

```python
docx_export(title, body, fragments, image_resolver=...)
```

**LaTeX → Office Math XML (OMML):**
- Блочные `$$...$$` → center-aligned OMML paragraph
- Inline `$...$` → inline OMML run
- Парсер `_math_fragments()`: рекурсивный descent для `\frac`, `\sqrt`, `^`, `_`, `\text`
- Поддерживает: дроби, корни, степени, индексы, греческие буквы, операторы

**Картинки:**
- Маркеры `[img:N.M]` → `image_resolver(N, M)` → `document.add_picture(path, width=Inches(5))`
- Caption добавляется как italic paragraph под картинкой
- Если resolver не задан или картинка не найдена → маркер просто удаляется

## Зависимости

| Библиотека | Назначение | Обязательная |
|-----------|-----------|:---:|
| `python-docx` | Создание DOCX файлов, OMML-формулы | Да |
| `genanki` | Создание Anki APKG пакетов | Нет (graceful fallback) |
| `graphviz` (системный) | Рендеринг DOT → SVG | Нет (показывает raw DOT) |
| `streamlit-agraph` | Интерактивные графы (альтернативный рендер) | Нет |

## Ключевые детали реализации

### parse_json_loose — устойчивый парсинг JSON от LLM

```python
def parse_json_loose(raw: str) -> dict:
    # 1. Убрать ```json...``` wrapper
    # 2. json.loads() — если повезло
    # 3. Fallback: найти первый { и последний } → json.loads(slice)
    # 4. Если результат list → {"items": list}
    # 5. Если ничего → ValueError
```

Это критично, потому что LLM часто добавляет текст до/после JSON, иногда не закрывает скобки, иногда оборачивает в markdown code block.

### Стабильные ID для Anki

```python
deck_id = _stable_int(deck_name)     # int64 из SHA-256
model_id = _stable_int("навигатор-химии-карточки")
note_id = _stable_int(f"{deck_name}:{вопрос}")
```

Это гарантирует, что повторный экспорт тех же карточек в Anki **обновит** существующие, а не создаст дубли.
