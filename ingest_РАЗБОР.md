# Разбор файла ingest.py

## Что делает этот файл

Берёт все PDF и DOCX из папки `all_pdfs/`, извлекает из них текст, режет на **чанки** (фрагменты ~800 символов) и сохраняет в `chunks.jsonl`. Каждому чанку автоматически присваивается один из 15 тематических кейсов через `cases.py`.

**Вход:** папка `all_pdfs/` с документами.
**Выход:** `chunks.jsonl` — по одному JSON на строке, формат:

```json
{"text": "...", "document": "s13321.pdf", "page": 3, "case": "токсичность"}
```

---

## Импорты и константы

```python
import os
import json
import pypdf
import docx
from cases import определить_кейс

папка_с_пдф = os.path.join(os.path.dirname(os.path.abspath(__file__)), "all_pdfs")
файл_чанков = os.path.join(os.path.dirname(os.path.abspath(__file__)), "chunks.jsonl")

размер_чанка = 800
перекрытие = 100
симв_на_страницу_docx = 2500
```

**Библиотеки:**

- `pypdf` — парсер PDF. Извлекает текст постранично. Не умеет в формулы и таблицы, но для чистого текста работает хорошо.
- `docx` (пакет `python-docx`) — парсер Word-файлов.

**Константы:**

- `размер_чанка = 800` — целевая длина каждого фрагмента в символах. 800 — компромисс: достаточно контекста для LLM, но не больше чем окно эмбеддинг-модели.
- `перекрытие = 100` — соседние чанки делят 100 символов. Это защита от того, что важное предложение попадёт на стык двух чанков и распадётся на два неполных.
- `симв_на_страницу_docx = 2500` — в DOCX нет понятия «страница» как в PDF, поэтому при чанковании режем виртуально — каждые 2500 символов считаем новой «страницей» для поля `page`.

## Извлечение текста из PDF

```python
def извлечь_текст_из_пдф(путь):
    страницы = []
    try:
        читалка = pypdf.PdfReader(путь)
        for номер, страница in enumerate(читалка.pages, start=1):
            текст = страница.extract_text()
            if текст and len(текст.strip()) > 50:
                страницы.append((номер, текст.strip()))
    except Exception:
        pass
    return страницы
```

**Что делает:**

1. `pypdf.PdfReader(путь)` — открывает PDF-файл.
2. Проходит постранично через `enumerate(..., start=1)` (нумерация с 1 как у человека, не с 0).
3. На каждой странице — `страница.extract_text()` достаёт текст.
4. Фильтр `len(текст.strip()) > 50` — пропускаем почти пустые страницы (обложки, пустые вторые страницы, страницы только с графикой).
5. `try/except` — если PDF битый или зашифрован, пропускаем весь файл молча.

**Возврат:** список кортежей `(номер_страницы, текст)`. Например, `[(1, "Intro..."), (2, "Methods..."), ...]`.

## Извлечение текста из DOCX

```python
def извлечь_текст_из_docx(путь):
    """DOCX не имеет явных страниц — режем виртуально по ~2500 символов."""
    try:
        документ = docx.Document(путь)
        куски = []
        for пар in документ.paragraphs:
            т = пар.text.strip()
            if т:
                куски.append(т)
        for таблица in документ.tables:
            for строка in таблица.rows:
                ряд = " | ".join(ячейка.text.strip() for ячейка in строка.cells if ячейка.text.strip())
                if ряд:
                    куски.append(ряд)
        полный = "\n".join(куски)
    except Exception:
        return []

    if len(полный.strip()) < 50:
        return []

    страницы = []
    номер = 1
    начало = 0
    while начало < len(полный):
        конец = начало + симв_на_страницу_docx
        кусок = полный[начало:конец].strip()
        if len(кусок) > 50:
            страницы.append((номер, кусок))
        начало = конец
        номер += 1
    return страницы
```

**Особенность DOCX:** в отличие от PDF, в Word нет фиксированной страницы — её определяет только рендеринг под конкретный шрифт и размер бумаги. Поэтому:

1. **Собираем весь текст** в одну строку:
   - Параграфы (`документ.paragraphs`) — основной текст.
   - Таблицы (`документ.tables`) — обходим построчно, ячейки склеиваем через `|`.
2. **Склеиваем всё через `\n`**.
3. **Режем на виртуальные «страницы» по 2500 символов** — чтобы поле `page` было осмысленным числом (в UI видно «файл.docx, стр. 3»).

**`if len(полный.strip()) < 50:`** — пустой или почти пустой файл → пропустить.

## Разбиение на чанки

```python
def разбить_на_чанки(текст, размер, перекр):
    чанки = []
    начало = 0
    while начало < len(текст):
        конец = начало + размер
        кусок = текст[начало:конец].strip()
        if len(кусок) > 80:
            чанки.append(кусок)
        начало = конец - перекр
    return чанки
```

Классический sliding window: окно шириной `размер`, сдвигающееся на `размер - перекр` (700 символов).

**Пример на тексте длиной 2000 символов:**

- Чанк 1: [0, 800]
- Чанк 2: [700, 1500]  ← первые 100 символов повторяют хвост чанка 1
- Чанк 3: [1400, 2000]

**`if len(кусок) > 80:`** — выбрасываем микро-чанки в конце (<80 символов) — они обычно содержат обрывки одной фразы и не несут смысла.

**Почему не делим по предложениям:** для научных статей на разных языках (RU/EN) универсальный токенизатор предложений трудно настроить. Грубое деление по символам работает в 95% случаев не хуже.

## Главный цикл: обход файлов

```python
все_файлы = sorted([
    ф for ф in os.listdir(папка_с_пдф)
    if ф.lower().endswith((".pdf", ".docx"))
])

print(f"Найдено файлов: {len(все_файлы)}")

счётчик_чанков = 0
счётчик_файлов = 0

with open(файл_чанков, "w", encoding="utf-8") as выходной:
    for индекс, имя_файла in enumerate(все_файлы, start=1):
        полный_путь = os.path.join(папка_с_пдф, имя_файла)
        if имя_файла.lower().endswith(".pdf"):
            страницы = извлечь_текст_из_пдф(полный_путь)
        else:
            страницы = извлечь_текст_из_docx(полный_путь)

        if not страницы:
            print(f"  [{индекс}/{len(все_файлы)}] ПРОПУЩЕН (нет текста): {имя_файла}")
            continue

        for номер_страницы, текст_страницы in страницы:
            чанки = разбить_на_чанки(текст_страницы, размер_чанка, перекрытие)
            for чанк in чанки:
                кейс = определить_кейс(чанк)
                запись = {
                    "text": чанк,
                    "document": имя_файла,
                    "page": номер_страницы,
                    "case": кейс
                }
                выходной.write(json.dumps(запись, ensure_ascii=False) + "\n")
                счётчик_чанков += 1

        счётчик_файлов += 1
        if индекс % 50 == 0 or индекс == len(все_файлы):
            print(f"  [{индекс}/{len(все_файлы)}] обработано файлов: {счётчик_файлов}, чанков: {счётчик_чанков}")

print(f"\nГотово! Всего чанков: {счётчик_чанков}")
print(f"Сохранено в: {файл_чанков}")
```

**Ключевые моменты:**

### `sorted(...)` для детерминированного порядка

```python
все_файлы = sorted([...])
```

Сортировка по имени обеспечивает одинаковый порядок чанков между разными запусками. Это критично для `embed_resume.py`, который догружает «хвост» — если порядок плавает, старые и новые чанки перемешаются.

### Диспетчер по расширению

```python
if имя_файла.lower().endswith(".pdf"):
    страницы = извлечь_текст_из_пдф(полный_путь)
else:
    страницы = извлечь_текст_из_docx(полный_путь)
```

`.lower()` — чтобы ловить и `.PDF`, и `.pdf`, и `.Pdf`.

### Формат выхода — JSON Lines

```python
выходной.write(json.dumps(запись, ensure_ascii=False) + "\n")
```

**JSON Lines (`.jsonl`):** одна строка файла = один JSON-объект. В отличие от обычного JSON-массива, можно читать построчно без загрузки всего файла в память.

**`ensure_ascii=False`:** без этого флага кириллица сохраняется в виде `\u041a\u0438\u0440` (экранированные коды). С ним — читаемо: `"Кир"`.

### Прогресс каждые 50 файлов

```python
if индекс % 50 == 0 or индекс == len(все_файлы):
    print(f"  [{индекс}/{len(все_файлы)}] ...")
```

Иначе на 577 файлах терминал забивается сотнями строк. Печатаем раз в 50 файлов + финальный шаг.

## Связи с другими файлами

- **`cases.py`** — импортируется `определить_кейс(текст)`, которая по ключевым словам относит чанк к одному из 15 кейсов.
- **`all_pdfs/`** — входная папка с документами.
- **`chunks.jsonl`** — выходной файл, потом читается `embed_resume.py` и загружается в Qdrant.

## Что будет если...

| Ситуация | Поведение |
|---|---|
| PDF зашифрован паролем | `try/except` поймает ошибку, файл пропущен с отметкой ПРОПУЩЕН |
| PDF содержит только изображения (сканы без OCR) | `extract_text()` вернёт пустоту, страница пропущена |
| В `all_pdfs/` есть `.txt` или `.jpg` | Фильтр расширений пропустит, не попадут в базу |
| Добавил новый PDF и перезапустил | Файл перезапишется целиком, все старые чанки заменятся на новые (+новые файлы) |

## Пример работы

**Вход:** `all_pdfs/example.pdf` с 5 страницами, на странице 3 текст про `"Bayesian optimization was used to improve reaction yield..."`.

**Шаги:**

1. `извлечь_текст_из_пдф` возвращает `[(1, "..."), (2, "..."), (3, "Bayesian optimization..."), (4, "..."), (5, "...")]`.
2. Для стр. 3: `разбить_на_чанки` делает ~3–4 чанка по 800 символов.
3. Для каждого чанка `определить_кейс` возвращает, например, `"выход_реакции"` (матчится по словам `reaction yield`).
4. В `chunks.jsonl` появляется строка:
   ```json
   {"text": "Bayesian optimization...", "document": "example.pdf", "page": 3, "case": "выход_реакции"}
   ```

## Что запомнить на защиту

1. **Sliding window с overlap 100** защищает от разрыва смысла на стыке чанков.
2. **Размер чанка 800 символов** — баланс: больше контекста vs ограничение эмбеддинг-модели.
3. **JSON Lines** — построчный формат для больших датасетов.
4. **Детерминированный порядок через `sorted`** нужен для инкрементальной загрузки в Qdrant.
5. **DOCX без реальных страниц** — виртуальная пагинация по 2500 символов.
6. **Авто-тегирование кейсов** происходит здесь, на этапе ingestion, а не при поиске. В Qdrant кейс уже лежит как поле `case` и используется для фильтрации.
